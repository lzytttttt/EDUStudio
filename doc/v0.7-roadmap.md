# v0.7 路线图 · 智能简报：可交互 × 个性化生成 × 仪式感决策

> 基于 v0.6.1 交付现状制定。v0.6 已完成：Harness 层自进化技能系统 / 技能库面板与演示向导 /
> 三栏拖拽调宽 / 界面字号全局调节 / 登录页改版。Vitest 104 例 + E2E 7 条全绿。
> v0.7 主线：**简报从「静态只读卡片」升级为「可交互、可个性化、可由 LLM 生成的智能简报」，
> 并以真实落章动效、顺滑卡片动效与专注模式强化决策的仪式感与沉浸感**。

## 背景与目标

「今日简报」是登录后的第一个舞台：用户以滑卡方式消费结构化卡片并做出跳过/收藏/采纳决策。
v0.6 后存在四类差距：

1. **生成靠硬编码**：简报是纯前端 Mock 剧本，API 模式是空壳（直接回退 Mock），LLM 不参与简报生成；
2. **内容只读**：卡片 payload（options/todos/editable）全部只读——选项不可点、待办不可勾、可编辑文本实际不可编辑；
3. **决策缺仪式感**：滑卡只有随力度淡入的「印章贴纸」，没有真实落章动效；卡片拖拽手感与堆叠联动生硬；
4. **采纳即跳转**：采纳后立即离开简报页，多卡批量批示被打断，缺少「批示完成 → 统一处理」的收束动作。

v0.7 五项升级：**① 简报生成增强（Mock 个性化 + API 骨架）② 内容可交互 ③ 真实落章动效
④ 卡片动效优化 ⑤ 专注模式**。

## 关键设计决策

1. **getDeckAsync 可选方法而非改同步签名**：`BriefingProvider.getDeck` 保持同步（现有调用点零破坏），
   API 生成走可选 `getDeckAsync`，briefingStore 存在即优先使用；同步 getDeck 始终返回 Mock 兜底。
2. **payload 覆盖层而非直接改剧本**：交互态（选中/勾选/编辑）按卡片 id 存 `payloads` 并持久化，
   loadDeck 时按 kind 判别合并——刷新/重进不丢交互态，且不污染 chart 等只读 payload。
3. **泵式顺序执行而非并发**：chatStore.sendMessage 有单飞约束（streaming + 单一 activeController），
   focusStore 泵逐个 await，完成后按条目 error 判定成败；单飞被占用时任务回队、泵退出，避免忙等。
4. **印章动效不引入 framer-motion**：沿用 tailwind keyframes + 内联 transform 体系（scripts/budget.mjs
   250KB gzip 包体门禁），SVG 滤镜仅作用于 76px 静态小元素，拖拽期间开销可忽略。
5. **决策联合类型内联在 types.ts**：`BriefingGenContext.decisions` 用内联联合类型，
   避免 harness 反向依赖 stores。
