# v0.9.2 路线图 · 工作台 UI 优化：把「工程师视角」换成「教育者的工作记忆视角」

> 依据《EDUStudio 工作台 UI 优化方案》（v1.0 · 2026-09-05）实施。v0.9.1 交付现状：
> 双闸门 + E2E + 视觉回归均通过。v0.9.2 主线：**不重设计、不换风格，只动信息架构与文案——
> 让执行轨迹讲人话、让默认视图直达主工作台、让任务列表按内容可找、让执行状态一眼可读**。

## 背景与目标

工作台模式运行一年后的用户视角评审发现四类「演示者视角」残留：

1. **执行轨迹露怯（P0）**：轨迹行显示 `searchCurriculum` 工具名与 JSON 返回体——
   教育者看不懂也不想看，技术细节反成噪音；JSON 展开入口无条件可见；
2. **主工作台藏了一层（P0）**：右栏默认 tab 恒为「文档」，教师每次进工作台都要
   手动点「工作台」才见出题面板，多一次无意义点击；
3. **任务列表不可找（P1）**：侧栏任务项只有标题 + `HH:mm` 时间戳，
   「上周四找的那个『分数乘法』练习」无法按内容定位；删除按钮 hover 才出现，移动端不可删；
4. **执行状态不可读（P1/P2）**：中栏头部只写「Agent 执行中」，第几步、几路并行全靠
   翻轨迹；「下发」tab 没有待回执提醒，批改回执被动等待。

v0.9.2 明确**不做**（记录决策，避免反复）：整体 Redesign、角色品牌色调整（维持 coral/mint/primary）、
引入新 UI 组件库（保持 Tailwind 3.4 + lucide）、演示剧本（方案 P2-B，不改代码）。

## 关键决策记录

1. **display 而非改 label**：label 继续供错误提示等场景使用，display 专门服务轨迹业务化；
   二者解耦，Mock/API 模式自动生效，无需改 Orchestrator。
2. **门控放渲染层而非事件层**：trace 事件照常携带 payload（调试数据不丢失），
   只在 JsonPeek 渲染处按 showTechDetails 决定是否出现入口——切开关即时生效，无需重放。
3. **进度口径**：tool_result 计数含并行组内多工具（每工具一条 result），
   但展示按 plan 步数封顶，避免「第 7/4 步」的视觉怪象。
4. **删除按钮常显**：与其纠结 hover 优雅，不如承认移动端是真实使用场景。
