## 0. 一句话与版本定位

**一句话**：不是再做一个功能更全的「备课百宝箱」，而是把教师升维成 **总指挥（Director）**——配一个 6 人虚拟战队（总指挥 / 学情分析师 / 命题官 / 备课研究员 / 家校沟通官 / 班务管家），让 **事找人、托管跑，只把决策留给教师**。

**为什么是 v1.0 而不是 v0.9.6**：v0.2 → v0.9.5 一直在补同一件事——「一个万能的、越来越厚的单 Agent 工作台」。v1.0 换的是产品支点：

| 维度 | v0.9.x（已交付） | **v1.0（本计划）** |
| --- | --- | --- |
| 入口 | 今日简报 / 工作台输入框 | **战情台（待我决策）** |
| 交互逻辑 | 人找工具：教师选卡、拆任务、追进度 | **事找人 + 异步托管**：系统拆任务、把活干到「只差拍板」 |
| 智能体形态 | 1 个 Agent / 用户角色（3 个 RolePreset） | **1 个战队 / 教师**：6 个专业化 Agent + 总指挥编排 |
| 编排 | 人在 Loom 画布上手动连线 | **系统按契约自动拆解 / 分派 / 并行 / 合成**，人只在审批门出现 |
| 产出 | 单份 Artifact 文档 | **作战包**（主件 + 附件 + 变更摘要 + 溯源 + 待决策清单） |
| 教师与 AI 的关系 | 用工具 | **带团队**（授权等级 / 表扬批评 / 战绩 / 复盘） |

> 版本号从 v0.9.5 跳到 v1.0，沿用本项目「主版本 = 产品形态变化」的口径。实施时同步校正版本漂移：`package.json:4` 仍是 `0.9.4`、README badge 仍写 408 例，与 v0.9.5 交付记录的 464 例 / 23 条 E2E 不一致，随本版统一。

### 本版成功的唯一判据

**10 分钟演示里，教师不打开任何一个「工具」，只做决策；离开屏幕 90 秒后回来，战队已经把一包活干完并等他签字。**

## 1. 立项动因

### 1.1 教师真正的痛点不是「不会写教案」，是「碎片时间 × 长链路事务」

现有 AI 教育产品默认教师有「一段完整时间 + 一个明确任务 + 一个会写 prompt 的脑子」。真实的一线教师不是这样：

| 时间 | 真实切片 | 对 AI 的含义 |
| --- | --- | --- |
| 07:10 | 早读盯班，10 分钟机动 | 只能做「看 + 点一下」的决策，不能进入工作台 |
| 07:50–11:30 | 2–3 节课 + 2 个课间，课间常被学生问题 / 矛盾占满 | 打断是常态；每次都要重新加载上下文 |
| 12:30 | 午休，批作业 + 回家长消息 | 只愿意处理「已经想好怎么办」的事 |
| 14:00–16:30 | 上课 + 教研 + 临时会议 | 长任务必须能后台跑 |
| 17:00 | 教务填表 / 督导回执 / 材料上报 | 有硬截止，却和教学事务争夺同一段精力 |
| 19:30–21:00 | 家长消息高峰 | 情绪与合规压力最大的沟通，最需要分寸 |
| 21:00 后 | 备课 / 出题 | 唯一完整的心流块，常被前面积压的事务吃掉 |

这不是「产品文案」，而是公开调查反复出现的结构：多项全国性调研（2017–2023，样本与方法不一，见研究备忘录 [01 §4](./v1.0-research/01-paradigm-and-competitive.md)）显示，约九成教师每天在校（含课后服务）超过 9 小时、约三成超过 11 小时；班主任周工作时长约 56 小时；教师约四分之三的时间花在非教学事务（材料、表格、迎检、家长工作）上，课堂教学仅占约 22%。**减负政策每年都在发，但「非教学事务」并没有消失，只是被更细地切碎。**

**真正被消耗的不是「生成能力」，是「编排能力」**：一件事从想法到落地要跨 3–5 个场景、4–6 个动作、2 个对象（学生 / 家长 / 教务），每换一次场景就要重新交代一遍上下文。现有单体 Agent 把编排成本留给了教师——它只在「一个 prompt 之内」帮忙，跨场景的部分全靠人肉路由。

**长链路事务的典型样本**（v1.0 全部围绕它们设计）：

| 长链路 | 跨度 | 涉及动作 | 现有产品的断点 |
| --- | --- | --- | --- |
| 单元考闭环 | 5–7 天 | 成绩分析 → 讲评 → 分层作业 → 家校沟通 → 复盘 | 一次只生成一份文档，前后不接 |
| 家长会闭环 | 3–5 天 | 数据准备 → 发言稿 → PPT 大纲 → 个性家长信 → 会后跟进 | 每份材料单独打开、数字口径不一致 |
| 督导材料回执 | 1–2 周 | 教务任务 → 证据收集 → 材料起草 → 回执提交 | 任务链存在但 LLM 参与不了（v0.9.5 才补管理侧工具） |
| 班级突发事件 | 数小时 | 情况了解 → 处置流程 → 家长沟通 → 记录归档 | 高情绪、高合规，AI 不敢做，教师全手工 |

### 1.2 现有产品已经验证了三块资产，v1.0 是升级不是从零开始

这是本计划敢做「战队」的前提——前 9 个版本已经攒下三块可复用的地基：

| 资产 | 现状（v0.9.5） | v1.0 的用法 |
| --- | --- | --- |
| **事找人的雏形** | 今日简报六类卡片、滑卡采纳、采纳即后台任务（`src/harness/scripts/briefing.ts:5-107`；`src/stores/briefingStore.ts`） | 卡片流升级为「决策卡」：不再是「有事」，而是「已备好方案」；简报退为首页发现区 |
| **编排的骨架** | Loom 空间任务台：任务图、依赖、拓扑串行执行、上游结果注入、人工确认暂停（`src/harness/loom/types.ts:12-57`；`src/harness/loom/runner.ts:147-224`） | 图算法 / 运行态 / checkpoint 复用；串行 runner 升级为 MissionRunner（并行 ready-set + 按 Agent 分派） |
| **信任基础设施** | 数字溯源 `{{值~来源}}`、数据上下文来源标注、记忆分层（L2/L3）、自进化技能、规则版自评、Mock 边界标识（doc/v0.9.5-roadmap.md 交付记录） | 成为战队的「质量与合规底座」：每个 Agent 的输出必须可溯源、可自评、可返工、可按授权等级放行 |

> 结论：v1.0 不需要重写产品，需要**换掉「谁来做编排」**——从人换成一个受约束的总指挥 Agent。

### 1.3 单体全能 Agent 撞上的天花板（为什么必须升维成「战队」）

当同一个 Agent 被要求「严谨统计考分」「设计天马行空的跨学科活动」「写高情商的家长安抚信」时，会同时出现三类失效：

| 失效 | 机制 | 现有代码里的症状 |
| --- | --- | --- |
| **目标函数互相稀释** | 一个 system prompt 里「零编造 / 可复核」与「发散创意」「情绪分寸」互相打架，模型只能折中，最终每个场景都「还行」但不专业 | `TEACHER_PRESET.systemPrompt`（`src/harness/roles/index.ts:13-16`）同时要求「教案给环节、试题标考点、学情引数据、语言亲切」——四个目标平铺 |
| **上下文污染** | 一次对话混入成绩、家长语气、创意素材、历史工具结果，后写的任务被前文带偏 | 现有 `Orchestrator` 用 `trimOldToolResults` / `compressToolRounds` 在 token 层裁剪（`src/harness/agent/Orchestrator.ts:491-568`）——症状级修补，不是职责级隔离 |
| **角色平庸化** | 单体没有「不做什么」的边界，也没有独立评价标准，无法被单独训练和授权 | `AgentTraceEvent` 没有 Agent 归属（`src/harness/types.ts:151-176`），无法回答「这封信是谁写的、它的质量标准是什么」 |

更深一层是三个工程事实——不是「模型不够大」，是**结构问题**：

1. **不能并行**：长链路上独立子任务（查学情 / 出题 / 拉家长数据）只能串行等；
2. **失败不隔离**：一次工具调用失败拖垮整条链，没有第二个人接手；
3. **不可分级授权**：同一个 Agent 既写内部教案又写对外家长信，授权只能一刀切「要么都信、要么都不信」。

**战队的本质不是「把 prompt 拆成六段」，而是把「职责边界、交接契约、评价标准、授权等级」四件事同时拆开。** 这是 v1.0 与原产品「多角色演示」的分水岭（详见 §5、§6.2）。

### 1.4 外部窗口：2026 年 9 月，个人 Agent 集体转向「常驻 + 主动 + 代办」

> 以下为外部研究结论，来源与「未证实」标注见研究备忘录 [01](./v1.0-research/01-paradigm-and-competitive.md)；本文只取与产品判断相关的部分。

**先拆同名**：用户提到的「dot / muse / cue」实际是 2026 年 9 月三周内密集发布的三款消费级个人 Agent——**Meta Muse**（2026-09-08）、**Manus Cue**（2026-09-28，随 Manus 2.0）、**OpenAI dots**（2026-09-29，复数）。另有一个更早的 New Computer「Dot」（记忆型 AI 陪伴），已于 **2025-10-05 停运并关停公司**——引用时必须区分，否则会误判「记忆型陪伴」这条路线。

| 产品 | 关键机制（研究 01 摘要） | 对我们的意义 |
| --- | --- | --- |
| **Meta Muse** | 消息式交互（App / WhatsApp）；关掉 App 继续工作，有变化或需审批才回来；可 forget；Secure VM + 独立 Sentinel Agent 守门；审批 + 审计轨迹 | 验证「异步托管 + 审批门」的交互可行；但通用场景（购物 / 旅行）缺交付物闭环 |
| **Manus Cue** | 每个 Agent 配独立邮箱 / 电话 / 钱包 / 电脑；多 Agent 可进同一群聊接力；预算内自主支付 | 验证「Agent 有身份」；但群聊「谁在回应谁 / 谁收尾」混乱，多 Agent 产出不显著优于单体（第三方实测） |
| **OpenAI dots** | 常驻智能体，独立云端电脑 + 大量应用插件；后台只读研究；规则式授权（允许 / 需批准 / 禁止）+ 活动视图；预告 specialist dots 与团队 dots | 验证「默认只读 + 分级授权」；官方也在走「专员 + 团队」路线，说明分工与编排是方向 |
| New Computer Dot | 强记忆 + 人格化陪伴，2025-10 停运 | 反例：**记忆不是壁垒**；没有场景与交付闭环，留存与成本撑不住 |

**这批产品验证了什么**：主动介入、长期记忆、异步执行、审批授权是真实需求，不是伪需求；**踩了什么坑**：下载 ≠ 留存（通用助手付费率极低）、单用户云端虚拟机成本高、主动推送变噪音、权限 / 身份 / 责任未解、通用助理缺场景锚点与交付闭环、多 Agent 协作本身不构成付费理由。

**给我们的四条判断**：

1. **记忆 → 场景 → 交付物 → 授权责任，四段链路缺一不可**。教育恰好四段齐全：学校时钟是触发器、文书交付是产物、家校/成绩是强合规、教师是天然责任人。
2. **多 Agent 必须证明 1+1>2**，否则只是把单体换皮成「多个聊天机器人」。所以 v1.0 的 demo 必须包含「单体做不到」的时刻（数字交叉校验 / 语气差异 / 合规拦截）。
3. **交接契约是成败点**，不是模型能力。外部多 Agent 产品的最大失败模式是「群聊里谁都能说、谁都不负责」——本计划用 typed handoff + citations 从机制上解决（§5、§6）。
4. **场景锚点即护城河**：通用个人助理没有「课表 / 校历 / 考试节点 / 教务 DDL」这组时钟；教师的时间碎片恰好需要「在正确的窗口推正确的决策」。这是「为什么是我们」的最强答案。

**国内竞品**（研究 01 §5）：主流仍是「单点生成」——希沃教学大模型（协同备课 / 课堂反馈）、讯飞星火教师助手（大单元 / 教学设计）、学科网组卷、班级优化大师、国家中小学智慧教育平台、豆包等通用入口。它们强在题库 / 生成 / 记录，**缺跨场景长链路编排、缺角色分工与审批、缺带溯源的教师个人记忆**——正是 v1.0 要占的位置。

## 2. 产品主张

### 2.1 用户升维：教师 = 总指挥（Director）

| 角色 | 在团队里做什么 | 产品对应 |
| --- | --- | --- |
| **总指挥（教师）** | 定目标、批计划、审关键节点、给反馈、调授权 | 战情台 / 作战室 / 战队 |
| **总指挥 Agent（首席幕僚）** | 听懂意图、拆任务、分派、催办、合成作战包；**不产出正文** | `chief` |
| **专业化 Agent（5 名）** | 各自岗位内的专业产出，有独立标准与「不做什么」 | 见 §5.1 |

### 2.2 三条交互原则（v1.0 的全部设计都从这里派生）

**原则一 · 事找人：不是推送「有事」，是推送「已完成的方案」。**

> **准备度法则（Prepared-Work Law）**：任何主动打扰教师的内容，必须满足「准备工作完成度 ≥ 80%」——教师只需做「采纳 / 改一句话 / 退回」三选一，且预计耗时在该时间窗允许的决策成本内（见 §4.5）。达不到就先在后台继续做，不许打扰。

- 这条例外于现有「今日简报」：简报是「今天值得做什么」，v1.0 的决策卡是「这件事我已经替你做完了，你来拍板」。
- 反模式：把 20 条待办推到首页；把「XX 成绩下滑」当警报推送（这是洞察，不是决策）。

**原则二 · 异步托管：教师离开是常态，不是等待。**

> 教师说一句话 → 战队拆解 → 确认作战计划 → **教师去上课，战队在后台跑** → 节点完成 / 需要审批时，以决策卡进入战情台 → 教师回来，只处理「需要我」的部分。

- 「异步」不是「慢」，是把教师的等待时间压缩为零；Agent 的并行与后台时间对教师不可见，只呈现结果与必要决策点。
- 诚实边界：本产品是纯前端 SPA，**不假装云端后台**——页签隐藏 / 关闭时任务暂停在安全点，回来显示「继续」；刷新按 localStorage 恢复（running→paused 续跑）。演示话术必须主动说明（见 §9 风险 5）。

**原则三 · 可管理：像带团队一样带 Agent。**

> 授权等级（L0–L3）、表扬 / 批评、已知偏好、近期战绩、周报——教师对「团队」的信任是可调节、可积累的，而不是「开关式信任」。

### 2.3 一句话差异化

> **「别人给教师一件更快的工具；EDUStudio 给教师一个会接班、懂分寸、可问责的虚拟教研组。」**

与市面形态的差异：

| 常见形态 | v1.0 的差异 |
| --- | --- |
| 工具箱 / 百宝箱：功能平铺，人来选 | 战队：目标进来，编排出去；首页没有功能列表 |
| 通用个人 Agent：记忆 + 主动提醒 | 有学校时钟（课表/校历/DDL）+ 真实交付物 + 审批与溯源 |
| 单体 Copilot：一个对话窗口解决所有事 | 六个岗位六个标准，typed handoff，交叉校验 |
| 全自动 Agent：一键生成一切 | 授权分级 + 审批门 + AI 草稿标识，对外动作永远人批 |

### 2.4 五条设计红线（防止做回「百宝箱 / 通知中心 / 聊天换皮」）

| # | 红线 | 具体判据 |
| --- | --- | --- |
| R1 | 不做工具目录 | 首页不得出现「功能宫格 / 应用列表」；任何新能力必须挂在某条 mission 或决策卡里 |
| R2 | 不做通知中心 | 进入战情台的每一条必须携带「已备好的方案 + 最小动作」；纯提醒只能进战报 |
| R3 | 不做聊天换皮 | 默认入口不是输入框；对话只保留一条极简「总指挥喊话」入口（插话通道） |
| R4 | 不做仪表盘堆砌 | 数据只在决策卡内部作为依据出现；首页 ≤3 个数字，0 张图表 |
| R5 | 不做全自动 | 对外发送 / 成绩公开 / 处分相关永远人工；AI 产物默认草稿态 |

## 3. 核心对象模型

> 字段级契约见 [v1.0-01-team-protocol.md](./v1.0-01-team-protocol.md) §3；这里只给概念与不变量，保证产品、交互、架构三方对齐。

| 对象 | 一句话 | 关键不变量 |
| --- | --- | --- |
| **Director** | 教师（登录身份，沿用 `RoleId`） | 只有 Director 能批准对外动作 |
| **AgentSpec** | 一个岗位：prompt / 工具白名单 / 输入输出契约 / 评价 rubric / 默认授权 | Agent 身份与用户 role **正交**；每个 Agent 必须有「不做什么」 |
| **Mission** | 一次委托：目标 + 交付物 + 任务 DAG + 审批门 + 预算 + 截止 | 任务 ≤ 8；必须声明「完成后交付什么」 |
| **TeamTask** | DAG 节点：一个 Agent 的一次专业产出 | 必须绑定 1 个 assignee；输出必须带 citations 或显式「无数据依据」 |
| **Handoff** | Agent 之间的交接物：typed artifact 引用 + citations + 约束 | **只传产物，不传对话**；下游只读声明过的上游产物 |
| **FactSnapshot** | 一次 mission 开始时冻结的班级事实快照（带来源与时间） | 全 mission 只读；任何数字必须能回溯到快照条目或上游产物 |
| **DecisionItem** | 事找人卡片：为什么现在找你 + 准备度 + 预计分钟 + 动作 | 准备度 < 80% 不得主动打扰；每条必须有「最小动作」 |
| **ApprovalGate** | 审批门：mission 中的硬暂停 | 未批准不得执行下游「对外 / 不可逆」动作；可暂停该分支、其余并行 |
| **AutonomyGrant** | 授权：Agent × 事项类型 → L0–L3 | 对外动作永远不高于 L1；敏感事项锁 L0；硬门不可上调 |
| **TraceEnvelope** | Agent 运行轨迹的外层信封（agentId / missionId / taskId / attempt / seq） | **不改**现有 `AgentTraceEvent` 联合类型（保 464 例回归） |

三个全局不变量（写进所有实现与测试）：

1. **总指挥不写正文**：`chief` 只输出计划、分派、催办、合成摘要；一旦它开始写家长信，就又变成单体。
2. **Agent 不读全局**：Agent 的输入 = 本任务目标 + 声明的上游 Handoff + FactSnapshot；**不读**其他会话历史（mission 内核 `history: []`）。
3. **没有出处的数字不许进对外产物**：数字必须能追到 `FactSnapshot` 条目或上游 Handoff 的 citation；追不到就降级为「建议」并标注「待核」。

## 4. 体验蓝图：四个表面

> 线框、状态表与完整分镜见研究备忘录 [03](./v1.0-research/03-director-ux-and-demo.md)；本节给可开发的骨架。

### 4.1 战情台（首页 · 事找人）

```
┌ 今日战情 · 11月10日 周一 · 09:42（课间） ┐
│ 待你决策 3 · 战队在办 2 · 今日已托管 4 · 约省 2h  │
│ [ 一句话交给战队去做…              ] ＋新委托     │
├ 待我决策（本窗口已推 2 条） ─────────────────────┤
│ ① 3 封家长信 18:00 前要发    P=0.91  [1 分钟]    │
│ ② 分层作业比例待定（函数单调性 61%）P=0.76 [50 秒] │
│ ③ 教研听课记录回执    下一课间提醒                 │
├ 战队在办（3 条） ────────────────────────────────┤
├ 今日简报 · 发现区（默认折叠）6 张 · 已批 4 ───────┤
└──────────────────────────────────────────────────┘
```

- **首屏只放决策**，不放功能入口、不放图表墙；「一句话委托」输入框是唯一主动发起入口。
- 决策卡六要素：谁做的 / 状态 / 为什么现在找你 / 准备度 + 预计分钟 / 可展开的预演 / 三选一动作 + 稍后（可复用简报卡的滑卡与落章动效：右=批准、左=稍后、↑=收藏）。
- 空态：「今天没有需要你决定的事」+ 3 条在办动态 + 委托入口 + 周报入口。
- 「稍后」= 进战情台不打扰，不丢失；错过窗口自动顺延到下一个窗口（不重复弹）。

### 4.2 作战室（Mission · 异步托管）

- **左**：使命与目标重述、战队状态；**中**：作战动态流（谁 · 做了什么 · 产物 · 用时）+ 插话；**右**：作战图（TeamTask DAG / 审批门，P0 用分层泳道，P1 再抽受控画布）+ 交付物。
- **头部**：进度 N/M · 预计剩余 · 暂停 / 撤回 / 插话。
- **四段式**：委托 → 计划确认 → 运行态 → 交付；计划确认单字段：目标重述 / 拆解（3–6 个 TeamTask，标 assignee、依赖、并行组）/ 交付物 / 审批门 / 预计（Agent 用时 + 教师介入次数）/ 成本（token 预算，沿用 `tokenBudget` 60000）/ 本次不做。
- **离开再回来**：回来三步卡「你离开了 1 分 30 秒 · 战队完成 4 个环节 · 1 件在等你」→ 时间线只显示 3 条关键节点 → 一键跳首个审批门。
- **插话**＝增量约束，不重启：总指挥须回执「收到，影响 2 个任务，重排后 +3 分钟」。**暂停**停在安全点；**撤回**删除未执行任务，已产出保留为草稿。

### 4.3 交付物（作战包 · 成果沉淀）

- 作战包 = 执行摘要（谁做了什么 / 关键决策 / 剩余风险 / 引用来源）+ 主文档 + 附件 + 教师 2 条待办 + 导出（复用 v0.9.5 真 docx/xlsx）。
- 在现有 Artifact 面板上增量：产物归属（mission / agent / 版本）、溯源 chip、「需审批」标记、发送动作（走审批门）。
- 交付物不是聊天的副产物，是作战包的组成；对外产物保留「AI 生成 · 人工复核」标识。

### 4.4 战队（Team · 可管理）

- 6 张成员卡：一句话职责 / 擅长 3 项 / 当前授权（按事项类型）/ 工具白名单摘要 / 近 7 天战绩 / 已学偏好（可删）/ 当前状态（待命 / 执行中 / 等你审批 / 暂停）。
- 授权矩阵：行 = Agent，列 = 事项类型（取数 / 草稿 / 家长发送 / 成绩对外 / 处分安全 / 公文回执），格 = L0–L3；硬门带锁，不可越过。
- 反馈：表扬 / 批评 + 一句话原因 → 进入该 Agent 的语义记忆与技能；连续 3 次驳回 → 授权降一级，连续 3 次通过恢复。
- 周报：授权使用（批/否/改）、战队产出、采纳率 / 返工率 / 省时估算、建议调整（一键采纳）。**周报是授权复议，不是 KPI 榜。**

### 4.5 「事找人」触发引擎

**触发源**（只允许五类，避免变成推送中心）：

| 源 | 例子 | 进入方式 |
| --- | --- | --- |
| Agent 产出 / 等审批 | 家长信草稿待批、教案待验收 | 决策卡（受窗口约束） |
| 数据异常（需判断） | 函数单调性掌握率 61%、专注度 86 | 先由分析师做成「方案」再进卡；未成方案只进战报 |
| 教务 / 任务链截止 | 督导回执 3/5、教研记录今天截止 | 决策卡（带已起草材料） |
| 课表 / 校历节点 | 明天习题课、D-3 家长会、公开课周五上报 | 提前 1–3 天进卡（准备时间窗） |
| 周期性复盘 | 周五战报、简报发现卡、家长咨询 | 不推送，只进战报 / 发现区 |

**优先级公式**（纯函数，可单测）：

```
P = 0.40·U + 0.30·I + 0.20·R + 0.10·M      （0–1，保留两位）
U 紧迫度：距截止 / 上课 / 发送窗口的剩余时间归一化（今天或 2h 内 = 1）
I 影响面：涉及学生数、是否硬截止、是否对外（对外或全班 = 1）
R 准备度：0–100%；< 80% 不得主动打扰，只进后台 / 战报
M 教师适配：与历史决策 / 偏好的匹配度（复用简报决策与记忆）
C 决策成本：1 / 2 / 3 分钟档——超过当前窗口允许成本则顺延；同分 C 小者先

阈值：P ≥ 0.65 主动推送；0.45–0.65 只进战情台；< 0.45 留战报 / 后台
算例：家长信 0.91、分层作业 0.76 推；督导回执 0.61 进战情台；简报提问卡 0.38 战报
```

**打扰预算与时间窗**：

| 窗口 | 时间 | 行为 | 上限 |
| --- | --- | --- | --- |
| 早读前 | 07:00–07:30 | 今日战情 + 最多 2 条决策（今天必须发生） | 占 1 次打扰，≤2 条，决策成本 ≤1 分钟 |
| 课间 10 分钟 | 课间 | 只推「已就绪的审批门」 | 占 1 次打扰，≤2 条，连续 2 个课间不重复，≤1 分钟 |
| 午休 | 12:30–13:00 | 家长信 / 学情小结 | 占 1 次打扰，≤2 条，≤5 分钟 |
| 下班前 | 17:00–17:30 | 验收 / 返工 / 明日准备 | **不占打扰预算**，≤10 分钟 |
| 晚间战报 | 21:30 | 只读摘要，不要求动作 | 不占预算 |
| 静默 | 22:00–06:30 与上课时段 | 只入战情台 / 站内红点，不推送 | 0 |

**主动打扰总预算：每天 ≤ 3 次**（早读前 / 课间 / 午休各 1 次；下班前与战报是「约定摘要」，不占用）。同一事项每天 ≤1 次；同一卡连续 2 次未读 → 静默至次日；紧急例外（截止 <2h 且对外）最多 +1 次，卡上必须写「破例理由」。

**堆积（>6 条）**：分「今天必须 / 今天可以 / 不必今天」三组，只出 1 条建议「先做这 3 件 · 合计 8 分钟」并支持批量；低风险 L1 转「仅存档」；连续 2 天堆积提示调授权。

### 4.6 授权与信任

**Autonomy L0–L3（本计划唯一口径，研究备忘录中的不同表述不作实现依据）**：

| 级别 | 语义 | 默认授予 |
| --- | --- | --- |
| **L0 旁观** | 只给建议与流程，不产出可发送内容 | 学生处分 / 心理 / 安全 / 涉隐私 / 对外承诺 |
| **L1 草稿** | 自动产出草稿，对外动作必须人批 | 家长沟通、成绩对外、教务上报（默认基线） |
| **L2 代办** | 内部产物自动完成、可撤回；对外仍走审批 | 教案 / 分析 / 练习 / 材料草稿 |
| **L3 全权** | 低风险内部动作自动执行，只汇报 | 提醒 / 日程 / 进度整理 / 归档 |

默认：总指挥只编排、不代批对外；学情分析师 / 命题官 / 备课研究员 L2；家校沟通官 L1（发送恒需人批）；班务管家 L3（内部提醒 / 清单），处分 / 心理 / 安全恒 L0（只给流程），考勤上报 / 对外回执 L1。

**审批矩阵与硬门**（不随授权等级放宽）：

| 事项 | 必须 | 说明 |
| --- | --- | --- |
| 发给家长 / 学生 | 人批 + 可编辑 | 发送动作本身永远 L1 |
| 成绩公开 / 排名 | 人批 + 溯源复核 | 成绩与姓名同时对外属硬门 |
| 教务 / 督导上报 | 人批 + 回执留痕 | 复用任务链回执 |
| 学生处分 / 心理 / 家庭隐私 | 全程人工，AI 只给流程建议（L0） | 不生成定论性文字 |
| 内部产物（教案 / 练习 / 分析） | 可 L2 自动 | 保留「AI 草稿」标识与撤回窗口 |

**信任的三个可见性**：① 每个数字 hover 可溯源（复用 v0.9.5 `md-cite`）；② 每个产物标「谁做的 / 依据 / 复核人 / 改了哪版」；③ 每个 Agent 的授权与战绩可查、可改。**批评 / 表扬 → 记忆**：写入该 Agent 的语义记忆（复用 v0.9.1 记忆分层 + 技能库），下次注入 prompt，战报体现「已学会」。

## 5. 战队编制与编排协议

### 5.1 六个 Agent（一句话版；详细规格见 team-protocol §2）

| Agent | 岗位 | 不做什么 | 典型产出 | 默认授权 |
| --- | --- | --- | --- | --- |
| **总指挥** `chief` | 首席幕僚：听懂、拆解、分派、催办、合成作战包 | **不写正文**、不取数、不报数字、不做学科判断 | 作战计划 / 任务分派 / 汇总摘要 / 催办 | 只编排（不代批对外） |
| **学情分析师** `analyst` | 把成绩/作业/专注度变成可引用的学情简报与分层名单 | 不出题、不写家长信、不归因到具体师生 | 《班级学情简报》、薄弱点清单、分层名单（带溯源） | L2 |
| **命题官** `assessor` | 按考点/难度/分层命制试题与作业单 | 不做诊断（只消费分析师结论）、不写教案、不超纲 | 分层练习、双向细目表、难度分布 | L2 |
| **备课研究员** `curriculum` | 教学设计：教案、环节、跨学科活动、课件大纲 | 不碰成绩统计口径、不写对外沟通、不自行计算数字 | 教案、活动方案、课件大纲 | L2 |
| **家校沟通官** `communicator` | 家长会讲稿、个性化家长信、安抚信、沟通口径 | 不编造数字、不做处分结论、不群发、未批不发 | 讲稿、信件草稿、沟通清单 | **L1**（发送硬门） |
| **班务管家** `steward` | 日程、清单、回执、材料归档、事件处置流程 | 不做教学判断、不写家长信正文、不生成处分建议 | 待办清单、回执材料、处置流程、提醒 | L3（对外 L1） |

### 5.2 编排协议（七步）

```
① 委托：教师一句话（或决策卡采纳）
② 拆解：总指挥判断「必须拆」四判据（跨≥2 专业域 / 需≥2 类工具 / 有审批门 / 产出>1 份）
        → 产出作战计划（≤8 任务、2 层为主上限 3 层、标注可并行）
③ 确认：作战计划卡 → 教师 [确认开战] / [自然语言修改]（默认 10 秒内）
④ 分派：MissionRunner 按 DAG ready-set 分派；并行上限 2（API）/ 模拟（Mock）
⑤ 交接：每个任务只读声明的上游 typed Handoff + FactSnapshot；输出带 citations
⑥ 校验：数字溯源 / 语气合规 / 权限敏感三道校验 + 总指挥合成；不合格退回该 Agent 返工（≤2 轮）
⑦ 交付：作战包 + 待决策项 → 决策卡进战情台 → 教师审批 → 归档 / 反馈
```

失败分支（必须可演示）：任务超时 → 重试 1 次 → 仍失败则该分支降级为「建议」并如实标注 → 其余分支继续，mission 标 `partial`，不整单报废。

**冲突仲裁顺序**：分析师的数据 > 其他 Agent 的转述；教师批注 > Agent 偏好；合规 > 语气。数字冲突时两个都保留、都标来源，由教师拍板，不私选。

### 5.3 为什么分工一定比单体能打（三个可演示对比）

| # | 单体的问题（同一条 prompt 内） | 战队做法 | 演示看点 |
| --- | --- | --- | --- |
| 1 | 家长信里的「班级均分 82.4」与学情统计口径打架；单体倾向「圆滑地圆过去」 | 分析师产出带引用的学情简报；家校官只能引用；校验发现不一致 → 退回重核 | 现场指出一处「物理 82.4 被写成班级均分」，系统自动拦下并改为三科均分 80.4 |
| 2 | 「跨学科活动要天马行空」与「考分统计要零编造」在同一段上下文里互相稀释 | 备课研究员高创意（发散提示），分析师零编造（引用约束）；各自 rubric 独立评分 | 同一委托里，活动方案有创意、报告数字全部可追 |
| 3 | 对外沟通要「高情商」、教务通知要「公文体」，一个 Agent 两种语气都不像 | 家校沟通官独立 prompt + 语气/合规 rubric + 强制人批；班务管家只写公文 | 家长信与督导回执并排展示，语气差异一眼可见 |

> 这三个对比是 demo 的「战队 > 单体」证明点。**四个校验规则（数字溯源 / 语气合规 / 权限敏感 / 数字冲突仲裁）必须做成规则模块并单测固化**，不能只写在 prompt 里。

**关键结论**：现有架构能承载「一个用户的一句话任务」，承载不了「多个 Agent 并行 + 跨任务交接 + 按 Agent 归属的 trace」。这正是 v1.0 要补的层，且不需要重构现有三层。若把 Mission 直接塞进现有 Loom / chatStore，会踩五个坑：单飞吞并行、会话即上下文边界、输出自由文本不可校验、Mock 里 Agent 人设不生效、无审批/预算/重试语义（研究 02 §一已逐条列出）。

### 6.2 架构决策（D1–D13）

| # | 决策 | 理由 | 次选 |
| --- | --- | --- | --- |
| **D1** | **Agent 与用户角色正交**：`RoleId` 仍是登录身份；新增 `AgentId`，不把 6 个 Agent 做成 6 个 RolePreset | 现有工具/剧本/数据上下文/测试都按 role 组织；扩 role 会连锁污染 | 6 个 RolePreset（否决：role 语义崩坏） |
| **D2** | **新增 `harness/team/` 层 + `MissionRunner` 调度外壳，复用现有 `AgentProvider` 执行单任务** | chatStore 是全局单飞 + 会话模型，无法表达并行 Agent、按 Agent 归属 trace、mission 级暂停恢复；MissionRunner 不写 chatStore、不抢 activeId，新增模块级 `ConcurrencyGovernor`（2 许可、前台优先） | 扩展 chatStore 成多 lane（改动面大，风险高） |
| **D3** | **Handoff 用 typed artifact + citations，不传对话** | 防上下文污染的核心机制；也是「团队」与「多个聊天机器人」的分水岭 | 共享一个对话上下文（否决：污染回到单体） |
| **D4** | **总指挥拆解双路径**：Mock 模板（演示确定性）+ API LLM（JSON schema 校验，失败回退模板） | 演示零翻车是项目一贯取向；API 路径保证真实能力 | 纯 LLM（不可控）/ 纯模板（能力假） |
| **D5** | **并行 ready-set，并发上限 2**；单任务超时 90s、失败重试 1 次后降级标注 | 真并发才能演示「团队」时间优势；上限 2 控成本与 Mock 复杂度 | 全串行（演示无时间差）/ 无上限（成本失控） |
| **D6** | **战情台是派生视图**：DecisionItem 由 mission 状态 + briefing 触发 + taskFlow + 时间窗计算得出 | 避免「第二套任务系统」；与 Loom 的「视图不持有真相」原则一致 | 独立 inbox 服务（过度设计） |
| **D7** | **溯源前置到契约**：Mission 开始时冻结 `FactSnapshot`，输出 citations 必须指向快照或上游产物；不合格退回，不静默改写 | 把 v0.9.5 的溯源能力升级为流程约束 | 仅 UI 展示（演示可信度不足） |
| **D8** | **复用 Loom 图算法做作战室 DAG；P0 用分层泳道视图，P1 再抽受控 GraphCanvas**（不复用与 store 强耦合的 `LoomCanvas`） | 图算法（拓扑/环/就绪判定）纯函数可直接复用；`LoomCanvas` 560 行且被 9 条 loom e2e 覆盖，P0 直改风险高 | 新写 DAG 渲染（重复造轮子）/ 直改 LoomCanvas（P0 风险） |
| **D9** | **新增 trace 用 `TraceEnvelope` 外层包装，不改 `AgentTraceEvent` 联合类型** | 保 464 例回归；UI 按 agentId 分栏 | 扩 11 种事件（触达投影/测试，P0 收益低） |
| **D10** | **存储：mission 独立键 `edustudio:missions` + `edustudio:team` + `edustudio:inbox`，schemaVersion + migrate，纳入备份白名单**；不并入 loom | 规避迁移与包体风险；inbox 的窗口计数需要跨刷新保持以执行打扰预算 | 并入 loom（迁移/包体风险）/ 全内存（预算失效） |
| **D11** | **新页面全部懒加载；主 chunk 120KB 不动，全部 JS 分阶段重校 310→325→335→350** | 主 chunk 只剩 0.9KB（实测）；不静默抬阈值 | 抬主 chunk 阈值（违反既有决策） |
| **D12** | **Mock 优先保证演示**：`?demo=1` 预置进行中 mission 与决策卡；每个 Agent 强制绑定 `mockScriptIds` | 项目定位是「路演可信」；且 Mock 不消费 systemPrompt，不绑剧本则六个 Agent 一个味 | 全走真 LLM（现场延迟不可控）/ 只靠 prompt 让 Mock 有差异（无效） |
| **D13** | **总指挥不持有业务工具**：拆解 / 校验 / 合成是纯函数与规则模块，不走 function-calling | 防止「总指挥」膨胀成新的全能单体；也避免它绕过 Agent 直接取数写文 | 给总指挥全部工具（否决：角色边界消失） |

### 6.5 包体与性能预算

实测基线（v0.9.5 交付）：主 chunk 119.1 / 120KB，全部 JS 304.7 / 310KB。主 chunk 只剩 0.9KB —— **v1.0 任何首屏新增都必须走懒加载**。

| 阶段 | 新增源码估算 | gzip 增量 | 主要落点 | 主 chunk | 全部 JS 建议阈值 |
| --- | --- | --- | --- | --- | --- |
| P0 | 40–50KB | +11–15KB | planner / runner / store / 战情台与作战室 UI / 适配 | ≤+0.9KB | 310 → **325**（P0 后按实测重校） |
| P1 | 25–35KB | +7–10KB | 成员卡 / 授权矩阵 / 审批恢复 / 作战图画布 | 0 | → **335** |
| P2 | 30–40KB | +8–12KB | 拆解质量 / 契约校验 / 成本报表 / L2-L3 托管 | 0 | → **350** |

依据：v0.9.5 实测「约 9KB 源码 → +8.9KB gzip（含 3 个懒 chunk）」；新代码以可擦除接口 + 中文文案为主，按源码 0.25–0.35 估 gzip；主 chunk 仅剩 0.9KB，静态 import 即破门禁。**必须懒加载**：planner、runner、战情台 / 作战室 / 战队、作战图画布、成本报表。**反例**：为侧栏角标把 missionStore 拉进主 chunk。

**性能**：新页面首屏交互 ≤ 200ms（本地数据）；Mock 单步 400–900ms、整条 mission 8–15 秒内完成（演示节奏，不假装长等待）；真 LLM 模式单任务超时 90 秒、mission 三重预算（agentRuns ≤8 / tokens / wall-clock，80% 警示、100% 强制收尾）。

| 指标 | 目标 | 测量方式 |

### 8.3 原型验证计划（M0，5–8 名教师）

| 假设 | 验证方法 | 通过线 |
| --- | --- | --- |
| **H1 事找人**：教师更愿意处理「已备好方案」而不是自己发起任务 | Wizard-of-Oz 3 张决策卡 + 现有简报对比 | ≥4/5 优先处理决策卡；卡内 10 秒内能说出「要我干什么」 |
| **H2 异步托管**：教师愿意把长链路整包委托并离开 | 模拟离开 5 分钟再回来 | ≥4/5 愿意；回来审批 ≤3 次点击 |
| **H3 战队质量**：分工版优于单体版 | 家长信 / 学情简报盲评（5 维度 rubric） | 战队版平均 ≥ 单体版 +1.0（5 分制）；数字错误 0 |
| **H4 可管理**：教师愿意像带团队一样调授权 / 给反馈 | 访谈 + 现场操作 | ≥3/5 主动调整授权；能说清 ≥2 个 Agent 的差异 |
| 整体 | 访谈 + 使用意愿 | ≥70% 愿意下周继续用；SUS ≥ 70 |

> **Kill / 收窄判据**：若 H1 与 H2 均不达线 → 不投入完整战队，改为「v0.9.6 决策卡增强」（只把简报升级为准备好的决策卡），把战队延期；若 H3 不达线 → 保留战队交互但不宣称质量优势，先修 rubric 与交接契约。

## 10. 明确不做（本版范围护栏）

| 不做项 | 理由 |
| --- | --- |
| 真实家长消息渠道（微信 / 钉钉 / 短信）接入 | 合规与演示成本高；v1.0 只做「发送动作 = 模拟审批 + 登记」 |
| 多租户 / 账号权限 / 云端同步 | 演示型产品不需要；localStorage 定位不变 |
| 移动端完整功能 | 只做「战情台 + 审批」的移动轻操作（P2），不做移动端工作台 / 拖拽 |

| 校级 / 局级多教师战队协作 | v1.0 只做「教师个人战队」；校管 / 局角色保留现有能力 |
| 语音 / 多模态 / 视频分析 | 不属本轮交互重构；沿用既有课堂分析数据 |
| 100+ 任务大图调度 | mission 上限 8 任务；大图留给 Loom / 后续版本 |
| 全自动对外发送 / 无审批执行 | 红线 R5；对外动作永远人批 |
| 替换现有简报 / 三栏工作台 / Loom | 旧路径保留可达；v1.0 是做「新入口」，不是拆旧功能 |
| 学生级 AI 对话 / 学生端产品 | 目标用户是教师；未成年人数据最小化，不做学生侧对话 |
