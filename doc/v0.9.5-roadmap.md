# v0.9.5 路线图 · 路演可信度专项：让每一个数字都答得出出处

> 定位：**路演 / 展会演示型产品**。本版不加功能，只修「当场被问倒」的可信度缺口。
> 立项日期：2026-09-28 · 状态：待实施 · 零新依赖。

---

## 背景与目标

### 立项动因：验收标准从来没有回答过「用户得到了什么」

复盘 v0.2 → v0.9.4 的全部 roadmap，验收标准 100% 技术化：单测例数（149 → 408）、包体字节（117.9 → 118.4KB）、E2E 条数（8 → 23）、门禁是否 PASS。全库唯一带体验语义的指标是「20 个节点持续拖动无明显掉帧」与「无 >50ms long task」——**仍是性能，不是用户收益**。

`e2e/` 现有 21 例覆盖的全部是技术路径（`loom.spec.ts` 精确到「20 节点/30 边」的 smoke、连线坐标落子），**没有一条断言「教师从采纳到拿到教案需要几步、几秒、是否中途放弃」**。文档体系扎实的另一面是：`doc/README.md` 索引 20+ 条只增不减、从不归档。

结果是：工程与文档质量都很高，但**没有一次回答过「用户获得了什么」**。本版的标尺据此重设。

### 标尺：10 分钟路演里，三个最容易被当场问倒的瞬间

| # | 现场瞬间 | 现有产品会怎么崩 | 性质 |
| --- | --- | --- | --- |
| ① | 领导点开报告，问「**这个 86.4 是哪来的？**」 | 模板里的数字答不出出处。答「演示数据」则全场降级为看 PPT，答不出则数据中台叙事当场作废，连带后面「精准帮扶」建议全变空话 | **唯一能被证伪的一击** |
| ② | 领导当场双击导出的 `.doc` | `exporters.ts:195-199` 是 Word 兼容 HTML 伪装 `.doc`，打开弹「文件格式与扩展名不匹配」，表格塌陷、h1 巨大、页眉变正文首行 | 没做好，可救 |
| ③ | 「局里下个任务，区和校怎么同时看到？」 | `pending→acknowledged→submitted` 是全项目**唯一真实**的跨角色闭环，但依赖 proxy，会场断网即降级本地且无提示 | 可救但掉分 |

**排序按「证伪 > 没做好」**：真实性 → 闭环 → 产物。

### 为什么是 v0.9.5 而不是 v0.10

本版是**修可信度**而非加功能，用增量修复号（v0.9.x）更贴合性质——沿用 v0.9.1 / v0.9.2 / v0.9.3 的先例，三者都是同版本号下的专项迭代。

### 本版明确不做（记录决策，避免反复）

| 不做项 | 理由 |
| --- | --- |
| 真实 LLM 接入 | 现场延迟与不确定性是灾难，Mock 兜底反而更可控 |
| CSV 成绩导入入口复活 | 解析器 `lib/csvImport.ts` 与数据通道 `findImportedProfile` **仍完好保留**（14 例单测在线），随时可重启；本版不占路演时长 |
| 演示水印策略调整 | 保持 v0.9.0 M4 的 Mock 边界标识不动（见「风险与对策」已知局限） |
| 账号权限 / 多租户 / 审计日志、移动端 | 把演示型产品拖成生产工具的最快路径 |
| 简报跨天重置与 24 张剧本个性化 | 「今日简报」一周内内容完全相同，不致命，别在这轮碰 |
| 为包体余量反复重构 | 见下方门禁方案 |
| `doc/README.md` 索引归档 | 索引只增不减确已失序，但属文档债、不属产品债，另版清理 |

## 现状与改动文件

### 关键事实核验（本版实测，非引用旧文档）

**① 报告数字的准确诊断：不是「假数」，是「冻结快照」**

`src/harness/scripts/artifacts.ts` 的 report 模板正文里，写死的数字**逐字等于** `src/data/seed.ts` 的对应条目：

| 模板位置 | 写死内容 | seed 对应项 |
| --- | --- | --- |
| `:82` | 86.4 / 65% / 88.2% | `REGION_METRICS[0..2]`（`seed.ts:152-154`） |
| `:85` | 「12 所监测校中 9 所」 | `REGION_METRICS[0].note`「全区 12 所中小学」 |
| `:92` | 62.7% | `REGION_METRICS[3]`（`seed.ts:155`） |
| `:93` | 高一（7）班物理 -3.2 分 | `SCHOOL_ALERTS[0]`（`seed.ts:174-176`） |

**真正的根因不是数字假，是模板与数据层没有连接**：`ArtifactTemplate.render` 的签名是 `render: (goal: string) => string`（`artifacts.ts:17`），**拿不到任何数据**。所以改 seed 报告不动、换数据源报告不动——它是一份手工誊抄的副本，会随数据演进静默腐化。

**唯一真实的口径冲突**：`REGION_METRICS[0].note` 与模板都称「全区 12 所中小学」，而 `SCHOOLS`（`seed.ts:75-79`）只有 **3 所**。这是本版必须消解的矛盾。

**② 包体余量实测（阻塞项）**

```
dist/assets 全部 JS gzip   295.8 / 297 KB   余量 1.2 KB
主 chunk（index-*.js）     118.4 / 120 KB  余量 1.6 KB
LineChart chunk（recharts） 103.0 KB        懒加载，计入总包但不贡献首屏
```

> `doc/README.md:45` 仍记「117.9KB / 295.4KB」，已有 0.5KB 漂移，本次一并校正。

**③ 导出与水印现状**：`exporters.ts:180-208`，`md` 真 Blob、`.doc` 为 HTML 伪装、`pdf` 为 `window.print()` 手动另存；`:186-188` 在 mock 模式为**所有**导出追加「本文档由演示剧本生成，非真实模型产出」。

**④ 任务链是唯一真实闭环**：`data/taskFlow.ts:42-84` 三条种子（局→校、校→教师），状态机 `pending→acknowledged→submitted`；`stores/taskFlowStore.ts:93-131` 走 `POST /v1/flows` + 15s 轮询，失败降级本地。**但它不在 Agent 工具集里**（`tools/index.ts:265-280` 的 `TOOLS` 无相关项），LLM 参与不了。

## 技术方案

### 第 0 步 · 包体门禁（阻塞项，必须最先落地）

**风险**：真 docx 若引 `docx.js` / `JSZip`（约 +30~50KB gzip），门禁超限 30~50 倍。`scripts/budget.mjs` 超限 `exit 1` 且在 CI 中是**硬门禁**——后果不是做不完，而是「**功能做完了、构建挂了、现场没有可演示的版本**」，比缺功能更致命。

**方案**：

1. **手写最小 OOXML，零依赖**（沿用本项目一贯取向：自研渲染器、自研 Markdown、playwright 而非引入重型测试栈）。zip 走 STORE 不压缩（docx 允许），封装 `[Content_Types].xml` / `_rels/.rels` / `word/document.xml` / `word/_rels/document.xml.rels`，约 150 行。
2. **`totalJsKB` 297 → 310**，在 `budget.mjs` 注释中按 v0.6 / v0.8.4 / v0.9.3 / v0.9.4-03 既有先例格式写清重校依据，**不静默放宽**。
3. Excel 复用同一 zip 容器（改 `xl/workbook.xml` 骨架），边际成本极低。
4. **记账不处理**：`LineChart` chunk 103.0KB 对首屏零贡献却计入总包，是独立的口径复议对象，不属本版。

### P0-A · 报告模板按数据渲染

**契约扩展**：`ArtifactTemplate.render` 签名改为 `render: (goal: string, ctx?: RenderContext) => string`。可选参数保证 lessonPlan / notice / generic 三个模板零改动（它们本就不含数字）。

**数据来源**：Mock 路径当前在 `MockArtifactProvider.ts:11-12` 直接 `tpl.render(input.goal)`；改为先 `buildDataContext(role)` 再传入。`artifacts/adapter.ts:7` **已经 import 了 `buildDataContext`**——API 路径本来就在注入数据，改完两条路径对称，Mock 只是补齐既有能力，不新增架构。

**渲染口径**：报告的「总体情况 / 主要成效 / 存在问题」三节改为遍历 `REGION_METRICS` 与 `SCHOOL_ALERTS` 生成，不再誊抄。**判定原则：模板只留句式骨架，任何数字都不得出现在模板源码的字面量里。**

### P0-B · 预置演示数据包

`SCHOOLS` 由 3 所扩至 12 所（覆盖小学 / 初中 / 高中三学段与城东 / 城西 / 城北 / 城南四片区），`CLASSES` 与 `CLASS_LEARNING` 补齐到新学校，`REGION_METRICS[0].note` 的「12 所」与数据对齐。

**约束**：只补 `SCHOOLS` / `CLASSES` / `CLASS_LEARNING` 三张表的**规模**，**不动**已与简报剧本、Agent 剧本、宣传片对齐的具体数字（86.4 / 82.4 / 78.6 / 80.2 等）——那些是跨模块共享的锚点，改一处会连锁失配。

### P0-C · 数字可溯源

数据上下文已有 `meta.label`（来源标注）与 `formatAge`（新鲜度）机制，`formatClassProfile` / `formatSchoolOverview` / `formatRegionMetrics` 均已输出「（来源：xxx · N 天前）」。本步把这套标注**下探到报告正文的每个数字**——用脚注形式挂在指标后，hover 可见。成本极低，收益是把「证伪」转成「卖点」。

### P1-A · 任务链接入 Agent 工具集

新增两个 `ToolDef`（复用 v0.9.2 建立的 `display(args)` 人话文案契约）：

| 工具 | 角色 | 作用 |
| --- | --- | --- |
| `listTaskFlows` | bureau / schoolAdmin | 查询当前任务链与回执进度 |
| `dispatchTaskFlow` | bureau / schoolAdmin | 起草并下发任务链 |

**必须补 `display(args)`** —— 不补则轨迹行裸露工具名与 JSON，等于回退 v0.9.2 已解决的问题。注册进 `TOOLS` 数组与各角色工具集（`tools/index.ts:282+`）时，**教师角色不加**（下发是管理侧动作），与现有三角色工具集边界一致。

### P1-B · syncState 可见化 + 断网降级

`taskFlowStore` 现有的失败降级是静默的。改为显式状态并在 UI 呈现「本地已记录 · 服务恢复后自动同步」。**这是把弱点转为演示动作**：现场主动断网 → 状态如实显示 → 恢复后自动同步，比一路绿灯更可信。

### P2-A / P2-B · 真 docx + Excel

`exportDoc` 改走 `lib/ooxml.ts`：Markdown → OOXML 段落 / 标题 / 表格映射，保留现有封面、页眉、批注附录与水印能力。**依赖第 0 步**。

### P2-C · 文档版本 diff

现有版本历史只有快照列表 + 恢复（`artifactStore.ts` 上限 20 版），无对比。**列为候选**，按前序里程碑的余量决定是否进本版——10 分钟路演讲不完。

## 风险与对策

| 风险 | 等级 | 对策 |
| --- | --- | --- |
| **包体门禁 1.2KB + CI 硬门禁** → 交付了但构建挂、现场无版本 | 高 | 第 0 步最先落地并留重校依据；每项改动后跑 `node scripts/budget.mjs` |

### 踩到的坑

1. **`npm run build` 里 `tsc -b` 是 `vite build` 的前置**。tsc 一旦报错，vite 根本不跑，`dist` 保持旧产物——我一度把陈旧的 `dist` 当成新构建结果读了好几轮。**读包体数字前必须确认 vite 真的执行了**（看 `✓ built in` 那行和产物 hash 是否变化）。
2. **主 chunk 120KB 比预估紧得多**。P0 落地后即达 120.4KB（超 0.4KB），P1 再加两个工具后又到 120.1KB。逐条抠自己的代码收效甚微（一次改动只省 0.1KB），最后靠把三块「生成时才需要」的代码拆成懒加载 chunk 才把主 chunk 压回 119.1KB。**结论：本项目后续任何新增都应先问「这段代码首屏要跑吗」，不要先写再省。**
3. **`resolveFocus` 原设计会静默串数据**。`SourceProvider.getClassProfile` 查不到班级时回落到 `CLASS_LEARNING[0]`，若不校验 `classId`，「聚焦城南中学初二（3）班」会顶着高一（3）班的数字——正是本版要消灭的那类证伪。已加 `classId` 匹配校验 + 单测固化。
4. **`{{值|来源}}` 的 `|` 会撞 Markdown 表格**。溯源标记大量出现在表格单元格里，用 `|` 分隔会被表格解析器拆列。改用 `~`。
5. **模板有序列表不能用中文数字**。`一. 2. 3.` 混排时 `一.` 不是合法 Markdown 列表标记，会退化成散段。改为由下标算出的 `1. 2. 3.`（源码仍无数字字面量，`li(i)` helper）。
6. **OOXML 测试抓到两个真 bug**：封面 `h1` 误映射成 `Heading1`（应为 `Title`）；`inlineRuns` 用 `split` + 捕获组拆加粗时丢失了 bold 标记。均已修并补测。

### 遗留问题

1. **主 chunk 余量只剩 0.9KB**。下一版若要加首屏功能，先拆懒加载再动代码。P2-C（版本 diff）本就是因为这个没做。
2. **docx / xlsx 未在真实 Office 打开验证**。zip 结构与 OOXML 骨架已按规范核对，但「Word 打开不弹格式警告」这句话目前是结构推断。建议路演前用真机 Word 打开一次导出的 `.docx`。
3. **Mock 边界标识仍会出现在 docx 导出里**（`exporters.ts` 对所有导出追加「本文档由演示剧本生成」）。本版按决策不调整，话术预案见「风险与对策」。
4. **验收 #5（双窗口跨端回执）与 #6 的补推实测**依赖 proxy 部署，会场未部署时只能靠降级横幅 + 本地回执演示。
5. **`doc/README.md` 索引只增不减**仍失序（40+ 条），属文档债，按原决策留给下版。
6. **`classesWithLearning` 让部分班级没有学情数据**（c6/c7/c9 在 `CLASSES` 但无 `CLASS_LEARNING`）。班级下拉只列有学情的 7 个，聚焦到无学情的班级时报告如实留空——不再串数据，但也没有内容。
