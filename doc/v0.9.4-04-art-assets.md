## 一、背景与目标

`scripts/png-art/` 的输出目录是仓库根 `png/`（生成器 README 标注「成品在 `png/`，中间件不入库」），
但没有任何应用源码消费它。接线前逐项核验的现状：

| # | 接线前现状（实测） | 影响 |
| --- | --- | --- |
| 1 | `src/` 与 `public/` 下无任何 `*.png` / `*.svg` / `*.jpg`；无 `src/assets/`；无 `import x from './x.png'`；无 `new URL(...)` 资源用法；无 `import.meta.glob` | 23 张已生成的资源全部闲置，出图成本未兑现 |
| 2 | 简报六类卡（洞察 / 决策 / 创作 / 待办 / 数据 / 提问）只有 lucide 图标 + accent 色（`BriefingCardView.tsx:8-15`） | 类型靠文字和色相区分，扫读门槛高 |
| 3 | 三角色（教师 / 校管 / 教育局）在登录页只有 lucide 图标（`LoginScreen.tsx:13`），侧栏身份区纯文字 | 无「人」的形象，角色剧本的代入感弱 |
| 4 | 四处空态均为「图标方块 + 文案」：工作台首屏（`ChatPanel.tsx:27-34`）、文档（`ArtifactPanel.tsx:521-529`）、画布（`LoomPanel.tsx:302-317`）、简报（`BriefingPage.tsx:493`） | 空态视觉单薄，也不解释产品在做什么 |
| 5 | `index.html:6-11` 的 favicon 是内联 `data:image/svg+xml`；无 apple-touch-icon、无 web app manifest、无 theme-color | 无法「添加到主屏」；iOS 主屏图标缺失 |

目标（设计原则）：**图片只出现在真正表达信息的地方。** 不做装饰性铺图，不把 1.71MB 摊进首屏——
登录页背景那套手写 CSS 动效（点阵网格 / 漂移光斑 / 漂浮简报卡与工作台骨架）本身编码了产品语义且零字节，
**保留不动**，只替换品牌标。

## 三、技术方案

### 3.1 一个注册表：`src/theme/art.ts`

放在 `src/theme/` 与 `tokens.css` 同域（品牌 / 设计资源），不新建顶层目录。对外只暴露五个常量：

```ts
import type { CardType, RoleId } from '../harness/types'

export const CARD_ART: Record<CardType, string> = { insight, decision, creation, todo, data, question }
export const ROLE_ART: Record<RoleId, string> = { teacher, schoolAdmin, bureau }
export const MASCOT_ART: string
export const SCENE_ART: { emptyBrief; emptyCanvas; emptyDoc }
export const BRAND_ART: { markColor }
```

三条设计约束：

1. **`Record<CardType, string>` + 对象字面量就是穷尽性门禁**，比运行时断言更早（`tsc -b` 阶段）。
   新增一个 `CardType`（`src/harness/types.ts:55`）而漏配图 → 编译报错。类型来自 `harness/types`，
   符合「业务代码只依赖 harness 契约」。
2. **`RoleId` 与出图文件名存在口径差**：领域 id 是 `schoolAdmin` / `bureau`，而文件是 `role-admin` / `role-district`。
   这层映射只存在于注册表一处，并进单测固化（见 §五）。
3. **`MASCOT_ART` 不并入 `ROLE_ART`**：`mascot` 在领域模型里没有对应角色（`RoleId` 只有 3 个），
   塞进 `Record<RoleId, ...>` 会破坏其穷尽性。

注册表用**相对路径** `../../png/**` 静态 import。跨目录可行：`png/` 在项目根内，Vite dev 与 build 都支持；
TS 侧由 `src/vite-env.d.ts` 的 `/// <reference types="vite/client" />` 提供全局 `*.png` 模块声明，
`tsconfig.app.json` 的 `include: ["src"]` 不影响它（注册表本身在 `src` 内）。
这些相对路径**只出现在这一个文件里**，将来若要挪资源，改一处即可。

### 3.2 为什么不需要 `lazy()`

本方案的关键机制：**Vite 只为被引用的 PNG 各产出一个带哈希的独立文件，图片字节只在 `<img src>` 真正挂载时才被请求。**
URL 字符串躺在 JS 里不等于下载图片，也不会有 `modulepreload`（Vite 只对 JS chunk 做 preload）。

因此注册表可以静态 import 全部资源，渲染层按需挂载即可，无需按图拆 chunk。
对照 `ChatPanel.tsx:19` 对 `LoomPanel` 的懒加载注释——那条纪律约束的是**代码**，图片天然满足。

### 3.3 只有 4 张需要稳定 URL

`index.html` 只能引用绝对路径 `/x.png`，而 JSON 格式的 `site.webmanifest` 的 `icons[].src` 更无法指向带哈希的文件名。
所以 **icon 组是唯一必须占据稳定 URL 的资产**，做法是改生成器 manifest 里这 4 条的 `out` 路径，
**不做文件拷贝、不留副本**（改完 `run.py --verify-only` 仍全绿，验证契约未破）。

只对 `group: "icon"` 动刀的理由：它是 `kind: "icon"` 的**确定性代码产物**（`draw_icon.py` 绘制，只需 Pillow，任何平台可重建），
迁移风险最低；14 张 `kind: "gen"` 的资产依赖已 gitignore 的 `raw/`，一律不碰。

`site.webmanifest` **刻意不写 `"purpose": "maskable"`**：这批 icon 用的是 `pad: 0.0` + `allowEdge: true`，
圆角方块直接顶到画布边缘，圆形遮罩会切掉四角。要做 maskable 需按 `mark-color-512` 的 `pad_ratio=0.12` 留白处理再出一版 512，列为后续项。

**`og:image` 刻意留空**：它必须是绝对 URL，而本仓库同时存在 Cloudflare Workers / Vercel / Pages 三种部署形态，
没有固定 canonical host。塞相对路径是无效值。等生产域名定下来再补，或引入 `VITE_SITE_URL` 构建期注入。

### 3.4 包体与部署影响

| 项 | 增量（实测） |
| --- | --- |
| JS gzip | **+0.7KB**（14 条 URL 字符串 + 注册表 + 卡片头部结构调整）：主 chunk 117.9 → 118.4KB，全部 JS 295.6 → 295.8KB |
| 主 chunk（门禁 120KB） | 仍守 120KB |
| 全部 JS（门禁 297KB） | 仍守 297KB → **`scripts/budget.mjs` 无需重校准** |

`scripts/budget.mjs` 只 gzip 统计 `dist/assets/*.js`，**图片不进预算口径**——这一点必须写明，
否则后续维护者会误以为图片也被门禁保护。

| 部署产物 | 增量（实测） |
| --- | --- |
| `dist/assets/`（哈希化图片） | +1472KB / 14 张 |
| `dist/` 根（`public/` 拷贝） | +≈35KB（4 张图标 + `site.webmanifest`） |

首屏（登录页）只付 16KB 品牌标；各界面按进入才付：简报 ≈339KB（一屏多卡同屏）、
工作台首屏空态 +112KB、文档空态 +36KB、**空画布 +793KB**。
`vite.config.ts` 的 `manualChunks` 不受影响；`assetsInlineLimit` 默认 4KB，14 张全部远超，
不会有任何图片被 base64 内联进 JS（唯一小于 4KB 的是 2KB 的 `favicon-64.png`，而它走 `public/` 不经 import）。

## 六、风险与对策

| 风险 | 对策 |
| --- | --- |
| 跨目录 import（`src` 引 `../../png/`）出问题 | Vite 支持项目根内任意路径；TS 由 `vite/client` 的全局 `*.png` 声明兜住。路径集中在 `src/theme/art.ts` 一处；回退方案为「整体挪到 `src/assets/` + 同一提交内改 `manifest.json`」，改动面可控 |
| 视觉基线大面积失效 | 列入必做步骤（§五-7）。CI 的 visual job 本身是 `continue-on-error: true` 软门禁，不会硬红，但仓库既有纪律要求同步重生成 |
| 793KB 空态图在 ~320px 框内过采样 | 已知并接受。后续项：新增降采样变体（生成器侧，`kind:"gen"` 需要已忽略的 `raw/`），或挪到 `public/` 用普通 URL 交由 CDN 处理 |
| 角色形象视觉偏小 | 用渲染框尺寸补偿，**不上采样**；这是生成器 trim 逻辑的既定行为，改它属出图侧变更 |
| `tsconfig.app.json` 的 `noUnusedLocals` / `noUnusedParameters` 均为 `false` | 残留未用 import **不会**让 `tsc -b` 失败，因此必须手工修剪（`Sparkles`、`GraduationCap`、`School`、`Landmark`、`LayoutTemplate`），否则留下 lint 级债 |
| `png/` 与 `scripts/png-art/` 未跟踪 | 提交会一次性引入 ≈1.84MB 二进制；提交范围与时机需仓库所有者确认，不自行 commit。`.gitignore` 已排除 `raw/`、`.state.json`、`__pycache__/`、`vibe_images/`；`png/shot/`（已跟踪的 README 截图）保持原样 |
| 新增 PWA manifest 影响 Lighthouse 性能分 | 软门禁（`continue-on-error`）。登录页只新增 16KB 品牌标请求；审计 URL 不受 793KB 那张影响（仅空画布才拉） |
| 测试里想读文件系统 → `tsc -b` 报 TS2307 | 本仓库未装 `@types/node` 且禁止新增依赖。改为 Vite 原生 `?raw` 读内容，物理可达性下沉到 e2e 同源 GET（critical-path ⑧）。**后续写 `src/**` 测试请勿 import `node:*`** |
| 视觉基线「重生成」后其实没变 | `--update-snapshots` 默认 `changed` 模式在 diff 低于 5% 阈值时不写盘，会静默保留旧基线。改用 `--update-snapshots=all`；已在 §五-7 记录并更正 `visual.spec.ts` 头部注释的隐含前提 |
