# v0.3 专项 ④：质量保障

> 优先级：P2 ｜ 前置：v0.2 全部专项（SSE 解析器 / Orchestrator / parsePlanJson 均为新增契约）
> 目标：harness 契约单测 + 关键流程 E2E 进入 CI，锁住「Mock/API 双模式零业务改动」的核心资产。

## 一、背景与目标

v0.2 在 harness 层新增了大量纯函数与状态机（SSE 解析、delta 归一化、function-calling 循环、
Plan-JSON 容错、FallbackAgent），目前仅靠临时联调脚本验证。这些是 v0.3+ 所有迭代的承重墙，
需要自动化测试固化行为；同时关键用户流程需要 E2E 兜底。

## 二、现状与改动文件

| 现状 | 文件 | 改动 |
| --- | --- | --- |
| 无测试框架 | 新增 `vitest` + `src/**/*.test.ts` | 见任务拆解 |
| 无 E2E | 新增 `playwright` + `e2e/*.spec.ts` | 关键流程双模式覆盖 |
| build 无测试前置 | `package.json` | `build` 前置 `vitest run && tsc -b` |
| 临时联调脚本 | `scripts/test-api.ts` | v0.2 验证完成后删除，用例迁移至单测 |

## 三、技术方案

### 3.1 单测（Vitest，纯函数优先）

| 测试文件 | 覆盖点 |
| --- | --- |
| `src/harness/llm/sse.test.ts` | parseSSEChunk：正常事件 / 半包续接 / [DONE] / 注释心跳 / CRLF |
| `src/harness/llm/adapter.test.ts` | normalizeDelta：content/reasoning/toolCalls 分片/finishReason/空 delta；LLMError 状态码 |
| `src/harness/agent/orchestrator.test.ts` | parsePlanJson：裸 JSON / 代码块包裹 / 噪声前后缀 / 非法输入 / 非法 step 过滤 |
| `src/harness/agent/toolRegistry.test.ts` | listForRole 角色过滤 / has/get 未注册工具 |
| `src/harness/scripts/agent.test.ts` | matchScript：角色+关键词命中 / FALLBACK 兜底 |
| `src/lib/markdown.test.ts` | renderMarkdown：标题/列表/表格/代码块/XSS 转义 |
| `src/stores/*.test.ts` | settingsStore 持久化 round-trip / chatStore 事件队列顺序 |

流式测试用 mock ReadableStream 构造 SSE 字节序列（含分片切割），不依赖网络。

### 3.2 E2E（Playwright）

`e2e/workbench.spec.ts`（默认 Mock 模式，`VITE_E2E=1` 注入测试种子数据）：

1. 登录 → 今日简报采纳
2. 工作台发送目标 → trace 事件流（plan/tool_call/tool_result/artifact）→ done
3. Artifact 面板：生成 → 编辑 → 导出 Markdown（断言下载）
4. 设置页：模式切换 Mock↔API（API 侧仅验证 UI 与配置持久化，不发真实请求）

API 模式真实调用作为手动验收项（不进 CI，避免外部依赖抖动）。

### 3.3 CI 前置

```json
"scripts": {
  "test": "vitest run",
  "e2e": "playwright test",
  "build": "vitest run && tsc -b && vite build"
}
```

## 四、任务拆解

| # | 任务 | 优先级 | 依赖 |
| --- | --- | --- | --- |
| 1 | Vitest 接入 + 纯函数单测（sse/adapter/parsePlanJson） | P1 | — |
| 2 | harness 状态机单测（registry/scripts/markdown/stores） | P1 | 1 |
| 3 | Playwright 接入 + workbench 主流程 spec | P1 | 1 |
| 4 | build 前置检查 + 删除临时联调脚本 | P2 | 1-3 |

## 五、验收标准

1. `npm run test` 全绿，覆盖 v0.2 新增全部纯函数与状态机
2. `npm run e2e` 在 Mock 模式下全绿（登录→简报→trace→文档→导出）
3. `npm run build` 自动先跑单测，单测失败则构建失败
4. 覆盖率：`src/harness/` 行覆盖 ≥ 70%（vitest --coverage 报告）
5. `scripts/test-api.ts` 已删除，其用例语义被单测覆盖

## 六、风险与对策

| 风险 | 对策 |
| --- | --- |
| E2E 选择器随 UI 迭代脆断 | 关键元素加 `data-testid`；spec 只依赖 testid 不依赖样式类 |
| LocalStorage 状态串扰 | 每个 spec 前清空 storage（playwright fixture） |
| 单测拖慢构建 | vitest run 全量 < 10s；超阈值再拆 test:built 快慢通道 |
