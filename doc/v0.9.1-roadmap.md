# v0.9.1 路线图 · AI Native：记忆分层 + 产出自评闭环

> 依据《EDUStudio-AINative设计方案 v1.0》（2026-09-05）落地，目标版本 v0.9.1（v0.9 与 1.0 之间的小版本）。
> 定位：**填空而非拆建**——在不破坏现有 harness 契约的前提下，为 1.0 补上两块 AI Native 拼图：
> **记忆分层**（让 AI 越用越懂用户）与 **产出自评闭环**（让产出质量可度量、可自愈）。
> 一句话叙事：「AI 记得你，AI 评估自己，AI 越用越懂你。」——完全本地、零 LLM 额外成本。

---

## 一、背景与目标

### 1.1 现状缺口（设计文档实测）

| 现状 | AI Native 缺口 |
| --- | --- |
| 数据全平铺 localStorage（会话/文档/收藏/技能） | **无记忆时间轴**：AI 不记得「上周帮张老师做过什么」，每次冷启动 |
| 简报有 personalize（skip/fav/accept 决策） | 记忆只有「卡片级」，没提升到「偏好级/语义级」 |
| 文档生成后用户手动改，结束 | **无质量反馈回路**：产出好坏不回流，模型不进化 |
| v0.6 distill 已沉淀技能 | skills 是「工作流记忆」，但缺「用户事实记忆」 |

### 1.2 已核实的三个注入点（零破坏前提）

1. `src/harness/roles/index.ts` `buildSystemPrompt` —— 已有 **【用户偏好】** 拼接段（同步函数）
2. `src/harness/skills/distill.ts` —— 已有 skills 读写与角色过滤（`s.roles.includes(role)`）
3. `src/harness/briefing/MockBriefingProvider.ts` `personalize` —— 已消费 `ctx.decisions/favorites`

→ v0.6 起的 distill 角色隔离即「注入 C」，本版仅确认，无代码改动。

## 二、技术方案

### 2.1 契约扩展（`src/harness/types.ts`，+60 行）

严格按设计文档 2.4 / 3.2 接口草案新增（`MemoryEntry` / `MemoryProvider` / `MemoryProviderConfig` / `EvalResult` / `Evaluator`）；
`BriefingGenContext` 增加可选 `prefs?: MemoryEntry[]`（向后兼容，现有调用点零破坏）。

```ts
export interface MemoryEntry {
  t: number                                                    // 时间戳
  role: RoleId
  kind: 'episodic' | 'semantic'
  key?: string            // semantic 用：'teacher.pref.quiz.count'
  value?: unknown         // semantic 用
  goal?: string           // episodic 用：任务目标摘要
  outcome?: 'accepted' | 'rejected' | 'edited' | 'executed'
  ref?: string            // 关联 artifact/skill/card id
  confidence?: number     // 0-1
}

export interface MemoryProvider {
  record(input: MemoryEntry): Promise<void>
  recentEpisodic(role: RoleId, limit?: number): Promise<MemoryEntry[]>
  semanticFor(role: RoleId): Promise<MemoryEntry[]>
  extractPrefs(entry: MemoryEntry): Promise<MemoryEntry[]>
}

export interface EvalResult {
  score: number            // 0-10
  checks: { name: string; pass: boolean; weight: number }[]
  suggestions: string[]    // 未通过的检查 → 可执行建议
}

export interface Evaluator {
  evaluate(doc: { kind: ArtifactKind; content: string; role: RoleId }): Promise<EvalResult>
}
```

### 2.2 记忆模块（新增 `src/stores/memoryStore.ts` + `src/harness/memory/`）

- **单键存储优化**：设计文档的 `edustudio:episodic[]` + `edustudio:semantic{}` 双键**合并为单键 `edustudio:memory`**
  （`{ episodic: MemoryEntry[], semantic: Record<string, MemoryEntry> }`）——对齐 v0.9 备份白名单机制，
  新增一个白名单键即被「数据备份」全覆盖。zustand store 持有（复用 skillStore 模式）。
- **L2 情景记忆**：环形裁剪上限 200 条（超限淘汰最旧）。
- **L3 语义偏好**：同 key 合并策略——同 value 置信度加权 +0.05（封顶 0.99）；不同 value 时采用置信度较高者
  （相等取新值，败方置信度衰减 ×0.5），保证偏好可被新证据覆盖。
- **偏好提炼规则**（纯函数，导出供单测，规则版零 LLM 成本）：

| 触发 | 产出 L3 |
| --- | --- |
| accept/edited + 目标含「N 题」 | `{role}.pref.quiz.count = N`（0.8） |
| accept/edited + 目标含 Word/docx | `{role}.pref.export.format = 'docx'`（0.8） |
| accept/edited + 目标含「N 分钟」+ 教案/课时 | `{role}.pref.lessonPlan.minutes = N`（0.8） |
| rejected（artifact） | `{role}.avoid.last = 目标摘要`（0.6，负例） |
| 简报卡片 fav/accept | `{role}.pref.card.tag.{tag} = true`（0.6） |
| executed（任务完成） | 仅 L2 情景，不提炼 |

- **注入文本组装**（`src/harness/memory/format.ts` 纯函数）：`formatMemoryBlock(episodic, semantic)` 生成
  「【场景记忆】/【用户偏好】」两段——情景 ≤3 条（各 ≤60 字，`M月D日：目标（结果）`）、偏好 ≤6 条（置信度降序）；
  空输入返回空串，注入块总量 <400 字符控制 token 增量。

### 2.3 注入接线

- **注入 A（systemPrompt）**：`buildSystemPrompt(preset, p?, memory?)` 增加第三个**可选**参数
  `{ episodic, semantic }`（保持同步签名）；由 Orchestrator 在 async 上下文 `await recentEpisodic(role,3)` +
  `semanticFor(role)` 后传入。段序：【场景记忆】→【用户偏好】（UserPreferences 行与语义偏好合并为同一段）；
  无记忆且无偏好时输出与现状**逐字节一致**（回归基线不变）。
  MockOrchestrator 剧本驱动不改 systemPrompt，改为 emit reflect 事件展示注入内容（三连演示可见）。
- **注入 B（简报）**：`briefingStore.loadDeck` 从 memoryStore 读取该角色语义偏好装入 `ctx.prefs`；
  `personalize` 在既有档位之上叠加偏好 tag 加权（收藏 tag=0 前置 → 偏好 tag=0.5 → 默认 1 → 跳过≥2 次=2 沉底）；
  `ApiBriefingProvider` 将偏好并入 LLM 生成上下文（与 decisions/favorites 注入方式一致）。
- **注入 C（技能角色隔离）**：v0.6 已有，仅确认 + 记忆读取一律按 role 过滤。

### 2.4 产出自评（新增 `src/harness/eval/`）

`ruleEvaluator.ts`：按 ArtifactKind 的检查项权重表（纯同步字符串规则，权重合计 10 → 分数即 0-10）：

| kind | 检查项 | 权重 |
| --- | --- | --- |
| lessonPlan | 四段结构（目标/过程/板书/作业） | 4.0 |
| lessonPlan | 环节含时间标注（`N min` / `N 分钟` / `N'`） | 3.0 |
| lessonPlan | 字数 400–1200 | 3.0 |
| report | 关键结论 + 数据引用（`N%` / 小数） | 4.0 |
| report | 字数 200–2000 | 3.0 |
| report | Markdown 结构完整（H1+H2，无悬挂标题） | 3.0 |
| notice | 三要素（时间 / 对象 / 报送方式） | 5.0 |
| notice | 字数 200–1200 | 2.5 |
| notice | Markdown 结构完整 | 2.5 |
| generic / analysis | 含结论/建议段 | 4.0 |
| generic / analysis | 字数 150–1500 | 3.0 |
| generic / analysis | Markdown 结构完整 | 3.0 |

未通过项经建议文案表映射为可执行建议（如「教学环节补充时间标注（如 5 min / 12 分钟）」）。
UI（ArtifactPanel 自评卡）诚实标注 **「AI 自评 · 仅供参考」**，对齐 v0.9 M3 决策责任边界；
支持一键重新自评；文档生成完成后自动评估一次。

### 2.5 收割点（写入时机，全部 try/catch 静默不阻断）

| 事件 | 写入 |
| --- | --- |
| 任务 emit done（双 Orchestrator） | L2 情景（goal/outcome='executed'） |
| ArtifactPanel 导出（有编辑=edited，否则=accepted） | L2 + extractPrefs → L3 |
| ArtifactPanel「符合预期 / 不符合预期」 | L2（accepted / rejected）+ extractPrefs |
| briefingStore.decide fav/accept | L3 标签偏好 |

### 2.6 注册中心

`providerRegistry.ts` 的 `Providers` 增加 `memory` / `eval` 两成员（本地实现不分 mode，随配置缓存构建）。

## 五、验收标准

1. **单测**（可测试）：
   - 情景记忆环形裁剪（写入 205 条 → 保留最新 200 条）；
   - 语义合并（同 value 置信度加权、异 value 高置信度胜出）、偏好提炼五规则各命中/不命中；
   - 注入文本格式（空输入返回空串；含【场景记忆】【用户偏好】；条数与长度截断）；
   - 四类文档评分（高完成度模板 ≥8 分、残缺文本低分）、建议生成、score ∈ [0,10]；
   - `buildSystemPrompt` 无参输出与现状逐字节一致、含记忆时出现【场景记忆】段；
   - personalize 偏好 tag 加权排序；备份白名单含 `'memory'`。
2. **集成**（可演示）：Mock 模式连续两局同类任务——第二局执行轨迹出现「已注入记忆上下文」reflect 且产出贴合偏好
   （如试题数量偏好生效）；文档自评卡展示分数/检查项/建议；「不符合预期」后再次同类任务触发负例回避提示。
3. **质量闸门**：`npm run build`（Vitest + tsc）全绿；包体预算 270KB gzip 门禁通过；全角色记忆互不污染（教师记忆不进入教育局会话）。

## 六、风险与对策

| 风险 | 对策 |
| --- | --- |
| 注入改变既有 systemPrompt 输出（回归破坏） | 无记忆无偏好时逐字节一致；roles.test 固化基线 |
| 记忆写入异常阻断任务主链路 | 所有 record/evaluate try/catch 静默降级 |
| 语义偏好被低质量负例污染 | rejected 仅记目标摘要（避免误伤）；置信度封顶 0.99、可被新证据覆盖 |
| localStorage 容量 | L2 环形 200 条 + 语义 map 键数有限，单键 JSON 体积可控；随 v0.9 备份机制可导出 |
| Mock 模板被偏好替换破坏演示基线 | 偏好替换仅在偏好存在时生效，无偏好时剧本输出与 v0.9 完全一致 |
| 角色记忆串扰 | 记忆键以 role 为前缀，读取一律按 role 过滤（注入 C 既有约定延续） |

## 七、不做清单（与设计文档 v0.9 决策一致）

- ❌ 不做服务端记忆同步（维持纯前端轻定位）
- ❌ 不做 LLM 版 Evaluator（规则版足够，LLM 版二期）
- ❌ 不做跨角色记忆共享（角色记忆隔离是特性：教育局不见教师工作史）
- ❌ 不新增记忆管理 UI（`clearAll` / 数据备份已覆盖清空与迁移，YAGNI）
