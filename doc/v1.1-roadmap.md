## 3. 第 0 步 · 前置修复（P0，先于真 LLM）

> 原则：**先修数据，再接模型**；这几项不做，A 方向等于把错误放大。

### P0-1 修复数据上下文百分比重复 ×100

- **证据**：`src/harness/sources/dataContext.ts:41`（及格率/优秀率）、`:48`（作业完成率）、`:61`（校情周趋势作业率）三处 `Math.round(x * 100)`；而 seed 与 CSV 导入的对应字段已是 0–100（`src/data/seed.ts:110-114,201`；`src/lib/csvImport.ts:119-120,270`）。对账：`scripts/report.ts:134,137`、`agent/tools/index.ts:41`、`sources/dataCards.ts:44,66` 都按 0–100 直接加 `%` → **0–100 是唯一口径，dataContext 三处是孤例**。
- **修法**：去掉三处 `* 100`；0–1 小数的归一放 Source/CSV 边界（CSV 的及格/优秀率也按 `v<=1 ? v*100 : v` 归一，与作业完成率一致）。
- **测试**：把 `src/__tests__/dataContext.test.ts:18-19,25` 的 0.91/0.86/0.82 夹具改为 0–100，断言「及格率 91%、作业完成率 93%、作业 88%」；输出不得 >100%。

### P0-2 校正演示文案口径（t8）

- **证据**：`src/harness/scripts/briefing.ts:102` t8 正文「班级均分 82.4，较上次提升 1.8 分」；seed：物理 82.4（+2.1）、数学 78.6（-1.4）、化学 80.2（+0.8），无「班级均分」字段。director 侧 Comment 与数据已按物理均分/+2.1 校正（`src/harness/director/data.ts:4-8`），**只剩 t8 未改**。
- **修法**：改为「本次月考物理均分 82.4，较上次 +2.1 分」；要「班级均分」必须在 seed 增派生值 80.4 并标「派生」，不许文案自行发明。
- **测试**：简报剧本单测断言 t8 含「物理均分」「+2.1」、不含「班级均分」「1.8」；`doc/v1.0-roadmap.md` 附录 C 口径表同步。

### P0-3 最小事实与引用校验（FactSnapshot + verifyCitations）

- **目标**：先建立「数字从哪来」的最小机制，LLM 只能引用事实快照，不能自由生成数字。
- **设计**：
  - `src/harness/director/facts.ts`：planning 时从 `SourceProvider`（`src/harness/sources/index.ts:45-53`）冻结 9 条事实：82.4 / 78.6 / 80.2 分、+2.1 / -1.4 / +0.8 百分点、93%、86、61%；`80.4` 标 `derived`（三科均值）；每条 `{factId,key,value,unit,label,source,asOf,derived?}`，degraded 如实写。
  - `src/harness/director/verifyCitations.ts`（纯函数）：抽数字 token 按单位配对；命中快照/派生 → verified；同指标异值 → conflicts（复用 d-conflict）；无据 → unverified。**只校验「统计型数字」**；「3 封 / 8 页 / 12 题 / 15 分钟 / 46 份」入结构性白名单（否则无法 100% 溯源）。
  - 落点：planner 产出先校验，unverified 只标「待核」不阻上屏；Mock 产物 4 篇补齐引用（目前仅 `data.ts:213,216` 两处）。
- **测试**：82.4 过、80.4 需 derived、84 unverified、9100/1.8 conflicts、「3 封」结构性过；`data.ts` 全量扫描 100% 分型。

### P0-4 其他污染项（顺手清掉）

| 问题 | 证据 | 处理 |
| --- | --- | --- |
| 单位混用：trend 是百分点却加 `%` | `src/data/seed.ts:30`；`sources/dataCards.ts:153`；`scripts/briefing.ts:230` | facts 带 unit，按 unit 渲染 |
| 导入文档原文 + 说明直入 prompt（注入面） | `src/stores/dataStore.ts:121-131`；`agent/Orchestrator.ts:133,149-151` | v1.1 planner 不消费导入文档附件 |
| 预算形同虚设：只统计输出且默认 60000 | `stores/settingsStore.ts:77-78`；`Orchestrator.ts:206,214-216` | planner 自带约 2K tokens 上限 |
| 引导已读标记绕过 storage 抽象 | `src/stores/directorStore.ts:29-45` | 并入 `edustudio:director` 持久化（见 §5） |

### P0-5 演示护栏

- LLM 路径只在 `settings.mode==='api'` 且 key/proxy 可用时启用（与 `providerRegistry` 同源），**演示默认 Mock**；不提供页内开关，避免现场误触。
- 计划页必须显示计划来源：`真 LLM` / `模板兜底` + 一行 reason（`data-testid="plan-source"`）；失败不弹 toast，不阻断。
- 任何 LLM 调用：15s 超时、可中止、单次约 2K tokens 上限、失败即回模板；`?v1=1&llm=0` 强制模板供彩排/E2E。

## 4. 方案 A · 真 LLM 拆解接入（拆解真、执行假）

### 4.1 调用链（最小闭环）

```
InboxSurface 一句话提交
  → store.plan(utterance)
  → director/planner.planMission({ utterance, roster, facts, templateFallback })
      ├─ mode!=api / 无 key / proxy（reason=mock_mode|no_key）→ 模板
      ├─ new DeepSeekAdapter(config).streamChatRaw（1 system + 1 user；流式仅累积）
      └─ 失败/超时/非法 JSON → 重试 ≤2 次 → 仍失败回模板（reason=timeout|invalid|http）
  → validatePlan(plan)（8 条矩阵）
      ├─ 通过：本地补正后写 missionPlan/planSource → 计划页
      └─ 失败：不展示非法计划，回模板并标「模板兜底」
  → 教师「开战」→ 执行仍走 Mock 引擎（§4.5）
```

- **零新依赖**：复用 `DeepSeekAdapter`；仅扩展 `StreamChatRawOptions`（`src/harness/types.ts:28-31`）加 `temperature/maxTokens`，`src/harness/llm/adapter.ts:106-107` 合入请求体；未传时行为不变（旧简报/工具路径零影响）。
- **不做 function-calling**：拆解是一次结构化生成；单 system + 单 user + 严格 JSON 最稳、最快、最便宜。
- **中止/竞态**：`AbortController` 15s；卸载/取消/重提 abort；`requestSeq` 丢弃过期响应，防连点。
- **重试规则**：仅 TypeError/5xx/非 JSON/校验失败重试，第 2 次附失败原因；**401/403/404/429 不重试**直接模板（429 带 Retry-After；代理限流 10 次/分，见 `proxy/README.md:20`）。

### 4.2 计划契约（wire `MissionPlan` + 本地适配）

```ts
export interface MissionPlan {
  kind: MissionKind                 // 'parent_meeting' | 'exam_loop'
  title: string                     // ≤12 字
  tasks: { id: string; agentId: DirectorAgentId; title: string; deps: string[]; gate?: GateId }[] // 4–8
  gates: GateId[]                   // 1–2
  deliverables: TileKind[]          // director 中文 tile kind（见 §4.2 末）
  estimateMinutes: number           // 3–60
}
```

- **LLM 只产以上字段**；task id 重编号、seconds、feed 台词、gate 文案、产物 Markdown 全部本地补。
- **不破坏现有结构**：`MissionPlanTask`（`types.ts:73-78`）与 `MissionState.plan`（`:82-92`）保持原样，`MissionPlan` 适配成 `MissionPlanTask[]` 后交现有脚本引擎；`MissionStatus` 只加 `'paused'`。
- **必改**：`MissionGate` → `GateId`（加 `worksheet|lesson`）；`GATE_META` / `GATE_OWNER` 注册表补两门；`GATE_STEP_IDS` 与 `gateCount` 不得写死 t2/t3，**从 `plan.tasks.filter(t=>t.gate)` 派生**（否则 LLM 计划永远显示「2 次拍板」）。
- **deliverables 用哪套 kind**：用 director 现有中文 tile kind（`简报/讲稿/大纲/信件`）并扩展 `练习单/教案/摘要` + 对应 lucide 图标；不改 harness 的英文 `ArtifactKind`（避免旧渲染链牵连）。

### 4.3 Prompt 与参数

| 项 | 设计 |
| --- | --- |
| system ① | 只输出一个 JSON 对象，禁止代码块/解释/多余字段 |
| ② | 名册 6 个 agent 的 id/职责/boundary（`director/data.ts:18-79` 压成 6 行） |
| ③ | 4–8 任务、deps 无环 ≤3 层、可并行、对外发送与成绩类必须挂门、kind 二选一 |
| ④ | 数字只能引用事实快照，不得新造；无快照用定性描述 |
| ⑤ | 字段白名单与长度：title ≤20 字、estimateMinutes 3–60、不输出工具/URL |
| ⑥ | 无法拆解输出 `{"fallback":true}`，不要反问 |
| user | 原话（≤120 字、`<utterance>` 包裹并声明视为数据）+ 6–10 行 facts（值/单位/来源）+ 2 个 kind 说明 + 合法示例（见附录 A） |
| 参数 | temperature 0.2；max_tokens 800；timeout 15000ms；maxAttempts 2；stream 仅累积；约 <2K tokens；记录 planSource/latencyMs/model/字符数 |

### 4.4 validatePlan（8 条矩阵，纯函数）

| # | 检查 | 失败 |
| --- | --- | --- |
| 1 | kind ∈ {parent_meeting, exam_loop} | reject |
| 2 | 4 ≤ tasks ≤ 8 | reject |
| 3 | agentId ∈ AGENTS 且至少 2 个非 chief | reject |
| 4 | deps 引用存在、无环、最长链 ≤3 | reject |
| 5 | gates ⊆ GateId、1–2 个且都落在存在任务上（与 task.gate 冲突以 tasks 重算） | reject |
| 6 | deliverables ⊆ 允许集合、≥1、去重 | reject |
| 7 | title/estimate 合法范围（title 超长截断，不 reject） | 修正 |
| 8 | 可选 tool ∈ `toolRegistry` 且属该 agent 工具域（v1.1 不产 tool，留 v1.2 防线） | reject |

通过后本地补正：id 重编号 t1..tn、seconds、gate 文案、产物按 kind 取模板。**不静默改结构**（id/截断除外）；非法计划永不上屏；失败→重试 1 次→模板并显示 reason。

### 4.5 失败与降级（必须可演示）

| 场景 | 行为 | UI |
| --- | --- | --- |
| 未配置 key/proxy / mode=mock | 直接模板，不发起请求 | 计划卡角标「模板」+ reason「Mock 模式」 |
| 网络失败 / CORS / 5xx | 重试 ≤2 → 模板 | 角标「模板兜底」；不弹 toast |
| 401/403/404/429 | 不重试，直接模板 | 角标「模板兜底」+ 一行 reason |
| 超时（>15s） | 中止 → 模板 | 角标「模板兜底」 |
| 输出非 JSON / 校验失败 | 重试 1 次（附错误）→ 模板 | 同上；不展示非法计划 |
| 输出合法但与事实冲突 | 允许展示，数字标「待核」（P0-3） | 冲突 chip |

### 4.6 执行侧边界（重要）

- LLM 只负责「计划」；**执行仍由 Mock 引擎按计划跑**：`MissionRunner` MVP 按 `plan.tasks` 生成通用时间线（每任务 600–900ms + 每 agent 的 Mock 台词），按 `plan.gates` 插门，按 `deliverables` 从产物库取内容。
- **模板剧本（两条 kind）保留精修版脚本/产物**：模板兜底演示必须保持今天的水准；LLM 计划执行允许「通用 Mock 产物」（诚实标注）。

## 5. 方案 B · 状态持久化（刷新不丢、暂停可续）

### 5.1 持久化契约

- **新键**：`edustudio:director`，`schemaVersion: 1`：

```ts
interface PersistedDirectorV1 {
  schemaVersion: 1
  updatedAt: number
  decisions: DecisionItem[]          // 上限 12
  stats: DirectorStats
  mission: MissionState              // status: idle|planning|running|paused|waiting|done
  missionKind: MissionKind
  missionCursor: number              // 续跑位置
  planSource: 'template' | 'llm'
  autonomy: Record<DirectorAgentId, AutonomyLevel>
  guideSeen: boolean
  facts: Fact[]                      // 约 0.8KB，随计划冻结，校验一致
}
```

- **排除字段**：`toasts`、`artifactId`、`guideActive/guideStep`、`screen`（派生）、请求态/seq、定时器、滚动位置。
- **体积**：feed 30×120B + decisions 3×450B + mission ≤2KB + facts 0.8KB ≈ **<10KB**（目标 ≤30KB 上限）。
- 复用 `loadJSON/saveJSON`（不裸 localStorage）；guideSeen 从旧独立键迁移合并后删除旧键。

### 5.2 写盘与 flush

- 新建 `src/stores/directorPersistence.ts`：module 级 `createDebouncedWriter`（300ms，`src/lib/debouncedWrite.ts`）+ 待写快照（照抄 `loomStore.ts:51-83`）；store `subscribe` 比对「持久化切片」序列化结果再 schedule，瞬态字段不触发写盘。

## 11. 风险与对策

| # | 风险 | 等级 | 对策 / 触发器 |
| --- | --- | --- | --- |
| 1 | LLM 计划非法/不稳定 | 高 | 8 条校验 + 一次修复重试 + 模板兜底；非法计划永不上屏；route 拦截做确定性 E2E |
