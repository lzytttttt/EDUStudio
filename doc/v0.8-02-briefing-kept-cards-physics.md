# v0.8 增量优化 · 简报保留卡物理动效 / 拖回重新批阅（交付说明）

> 本专项为 v0.8.1 交付后的小型优化（用户反馈一项），随 v0.8.2 发布。
> 状态：✅ 已完成 · 单测（149 例，+2）+ tsc 验证通过，无新依赖，纯 transform/opacity 动画（合成器友好）。

## 背景与问题（用户反馈）

v0.7 的滑卡批示体验中，盖章后的卡片随离场动画**直接飞出消失**，带来两个问题：

1. **批示缺少「留痕」仪式感**：像真实批阅文件一样，盖过章的简报应当留在桌面上可见，
   当前页面批示完成后一片空白，只有进度条记录过程；
2. **误操作挽回成本高**：手滑跳过/收藏一张卡后，只能等全部批示完成点「重新过一遍」
   从头再来，无法单卡取回——查看、修改内容（选项/待办/正文）后重新批阅。

## 需求（简报模式 · 非移动端场景）

1. 已处理的简报**保留显示**：盖章后的卡片不消失，持续留在舞台内；
2. 拖拽甩飞的盖章卡使用**物理碰撞动效**：适当缩小、半透明，在当前页面运动后停留；
3. 用户可以**选中拖回**：取回卡片查看并修改内容，重新批阅。

## 实现

### 改动一：保留卡物理层（新建 `apps/briefing/KeptBriefingCards.tsx`）

| 项 | 说明 |
| --- | --- |
| 甩飞衔接 | 决策触发后不立即生成保留卡，等待离场动画结束（`EXIT_MS`）后，以「拖拽末位置 + 飞出偏移」为起点、沿甩飞方向赋予初速度——与 v0.7 离场动画无缝衔接，观感上是同一张卡继续飞行 |
| 物理运动 | 单一 rAF 循环驱动全部保留卡：**无重力，仅空气阻力**（速度/角速度指数衰减）+ 上下左右四向等弹性边界碰撞反弹（0.6）；动能耗尽（合速度低于阈值）或超时 3.6s 后定格，倾角收敛 ±14°，全部静止后循环自动停摆 |
| 缩小与半透明 | 飞行途中 850ms ease-out 收缩至 0.55 倍、320ms 渐显至 0.55 透明度后定格；弱动效偏好（prefers-reduced-motion）下跳过物理，按槽位直接铺在舞台下缘 |
| 盖章定格 | 保留卡持续展示决策印章（`StampMark strength=1`，位置复用新导出的 `STAMP_POSITION`），「已盖章」状态一目了然 |
| 性能 | 物理帧直写 DOM transform/opacity（不触发 React 渲染），仅合成器友好属性；上限 8 张（`prev.slice(-7)` 滚动淘汰）；窗口 resize 时刷新边界并把全部保留卡（含已定格）夹回舞台内 |

### 改动二：拖回重新批阅（`BriefingPage.tsx` + `briefingStore.ts`）

| 项 | 说明 |
| --- | --- |
| 取回交互 | 保留卡为整体拖拽面（卡面内容 `pointer-events-none`，hover 出现「拖回重新批阅」提示胶囊 + 主色描边）：pointer 按下即拿起（0.78 倍提亮、z-index 盖过卡组），松手后 CSS 过渡 240ms 飞回卡组中心并复原尺寸/透明度，落地瞬间交还卡组 |
| 撤回决策 | `briefingStore.revertDecision(cardId)`：移除决策、`processed` 回退、收藏联动移除（原决策为收藏时），并同步 localStorage 持久化；未批示卡片为 no-op |
| 置顶展示 | 页面级 `pinnedId`：取回的卡片无视卡组顺序直接作为当前卡展示（`visible.find(pinned) ?? visible[0]`），可继续使用选项/待办/正文编辑等交互，修改后重新拖拽批示；再次决策时自动清除置顶 |
| 保留层重置 | 「重新过一遍」与专注模式总结层重放时同步清空保留层与置顶态 |

### 兼容性

- **移动端零影响**：`useIsDesktop`（`min-width: 768px`，对齐 Tailwind md 断点）门控——保留层仅桌面渲染，移动端维持原「飞出即消失」行为，E2E 关键路径不受影响；
- 保留层为**会话级显示状态**（决策本身仍持久化）：刷新页面后决策保留、保留卡待下次批示时重建，属已知边界。
