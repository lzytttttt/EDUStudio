# v0.9 路线图 · 信任与健壮性：Agent 主路径修复 + 数据安全网 + 决策责任边界

> 基于 v0.8.1 交付现状与一次完整用户视角评审制定。v0.8.1 已完成：专注模式移动端操作 /
> 工作台多文档跳转。Vitest 147 例全绿，双闸门 + E2E + 视觉回归 + Lighthouse 均通过。
> v0.9 主线：**修复 API 模式 Agent 主路径的接线缺口，为纯 LocalStorage 数据补上「备份 — 恢复」
> 安全网，并为 AI 驱动的教育决策补上合理提示与 Mock 边界标识——让产品从「可演示」走向「敢托付」**。

## 背景与目标

用户视角评审发现三类问题，v0.9 逐一解决：

1. **Agent 主路径名存实亡（功能缺口）**：`Orchestrator` 声称「function-calling 优先，Plan-JSON 降级」，
   但 `tools` 定义从未进入 LLM 请求体——模型不知道有哪些工具可用，永远不会返回 `tool_calls`，
   API 模式所有任务型目标 100% 走 Plan-JSON 降级，工具调用的可靠性与效率低于设计意图；
2. **数据单点风险（信任缺口）**：会话 / 文档 / 收藏 / 技能 / 成绩 CSV 全存 LocalStorage，
   换设备或清缓存即全部丢失，且无整体备份入口；教师辛苦产出的教案说没就没；
3. **责任与模式边界模糊（预期缺口）**：AI 产出（帮扶方案 / 督导通知 / 分层练习）缺少
   「需人工复核」提示；Mock 模式剧本回复与真实 AI 难以区分，新用户产生错误预期；
   浏览器返回键直接退出站点、连接失败黑盒报错等细节进一步削弱信任。

v0.9 明确**不做**（记录决策，避免反复）：登录体系真实鉴权与服务端数据同步（维持纯前端轻定位）、
PWA 离线缓存（另行评估）。

里程碑总览：**M1 function-calling 接线 · M2 数据安全网 · M3 责任边界提示 · M4 Mock 边界标识 ·
M5 导航与返回键 · M6 导入文档化与内容新鲜度 · M7 诊断与细节打磨 · M8 质量与发布**。

依赖关系：M1 / M2 独立可并行；M3 依赖 M2（提示文案同层，弱依赖）；M6 内 ①→②→③ 顺序实施
（先开教育局导入按钮，再做全角色导入文档化与 prompt 输入框）；M7 的 E2E 去硬编码
依赖 M6④（卡组轮换改变卡片内容）；M8 收尾。

## 关键设计决策

1. **tools 走请求体、契约做可选扩展**：`streamChatRaw` 以可选 `options` 参数携带 tools 而非新开方法，
   Mock 与既有调用点零改动；tool_calls 分片累积、并行执行、失败降级等已验证逻辑直接复活。
2. **备份选 JSON 全量快照而非逐类导出**：一个文件救所有数据，恢复即覆盖 + reload，行为可预期；
   键名白名单过滤保证跨版本前向兼容（旧文件新键 / 新文件旧键均安全降级）。
3. **提示而非阻断**：责任边界与 Mock 标识一律采用常驻轻量标识（小字 / 徽标），不弹窗打断
   批示流——教师专注模式下快速批示的节奏优先，预期管理靠「首次引导 + 常驻小字」双通道完成。
4. **popstate 用 pushState 补历史而非引入路由库**：维持「无路由库」轻定位；分享 hash 路由
   优先级不变，避免历史栈与 hash 双轨冲突。
5. **卡组以周为粒度派生、第 0 组保持现状**：默认体验与既有 E2E / 视觉回归基线不变，
   新鲜感来自周更而非日更（内容池制作成本与重刷率的平衡）；E2E 用 clock API 锁定日期。
6. **导入以文档附件直通 LLM 而非结构化解析**：教育局区县表等文档形态各异，逐形态扩展解析
   模板成本高、覆盖面有限；改为文档原文 + 用户 prompt（导入页输入框）作为附件材料注入
   LLM 上下文，把「理解文档」交给模型；既有成绩 CSV 解析器保留，兼容既有已导入数据。
   附件设长度上限与 Mock 边界（Mock 不消费附件并明示），避免上下文膨胀与预期错位。

## 风险与对策

| 风险 | 对策 |
| --- | --- |
| DeepSeek 对 tools 支持异常或幻觉 tool_calls | 既有 `TOOL_FAIL_LIMIT`（连续 2 次失败切 Plan-JSON）与未注册工具兜底已覆盖；单测断言请求体含 tools，防止再次静默回归 |
| 导出文件含混淆态 apiKey 的泄露面 | 导出确认弹窗明示保管责任；文案引导生产环境走代理（key 只存服务端） |
| popstate 与阶段动画 / 分享路由冲突 | hashchange 分支优先；popstate 仅在非分享态处理；setStage 内部去重（stage 未变不动历史栈） |
| 卡组派生破坏 E2E 与视觉回归 | 周粒度 + 第 0 组即现状；E2E 用 `page.clock` 固定日期；批示循环断言结构化计数而非具体文案（M7②） |
| 导入文档超长撑爆上下文 / 成本失控 | 附件设长度上限，超限截断并在 UI 明示；prompt 输入框引导用户写明文档用途，减少无效 token；Mock 模式不消费附件，不产生隐性消耗 |

## 验收标准

1. API 模式执行「针对高一（3）班函数单调性薄弱点出分层练习」，trace 出现真实 `tool_call` 事件，
   不再恒走「模型未调用工具」降级；单测断言请求体含 `tools` 字段；
2. 设置页导出 JSON → 清空全部数据 → 导入恢复：登录态 / 会话 / 文档 / 收藏 / 技能 / 偏好 / 字号等完整还原；
   恢复未知键被过滤且提示；
3. 简报页与首次引导可见「AI 生成内容仅供参考，采纳前请人工复核」；confidence=1 卡片显示「建议人工核实」；
   文档导出入口与导入文档对话框各含对应提示；
4. Mock 模式下对话流出现「演示」徽标、导出文档含演示标注；切 API 模式后两者消失；
5. 工作台按浏览器返回键回到简报页（动画正常），不再直接退出站点；`#share=` 链接行为不变；
6. 三角色导入入口统一为「导入文档」（教育局可见并打开该按钮）：上传文档并填写 prompt 后，
   文档原文与说明作为附件材料进入 LLM 上下文，会话可引用其内容；导入页 prompt 输入框存在且留空可用；
7. 测试连接：断网、错误 Key、错误地址三种场景分别给出可区分的中文提示；
8. Vitest 约 164 例全绿、tsc 通过、包体预算 PASS、E2E 与视觉回归（锁定日期）通过。
