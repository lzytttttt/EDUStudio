## 三、技术方案

### 3.1 SSE 流式解析（DeepSeekAdapter.streamChat）

DeepSeek 兼容 OpenAI `/chat/completions`，`stream: true` 时返回 `text/event-stream`：

```
data: {"choices":[{"delta":{"content":"你"}}]}
data: {"choices":[{"delta":{"content":"好"}}]}
data: [DONE]
```

实现要点：

```ts
async *streamChat(messages: ChatMessage[], signal?: AbortSignal): AsyncGenerator<string> {
  const res = await fetch(`${this.config.baseUrl}/chat/completions`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${this.config.apiKey}` },
    body: JSON.stringify({ model: this.config.model, messages, stream: true }),
    signal,
  })
  if (!res.ok || !res.body) throw new Error(`LLM API ${res.status}`)
  const reader = res.body.getReader()
  const decoder = new TextDecoder()
  let buffer = ''
  while (true) {
    const { done, value } = await reader.read()
    if (done) break
    buffer += decoder.decode(value, { stream: true })
    // 按 SSE 事件边界切分；半包留存 buffer
    const lines = buffer.split('\n')
    buffer = lines.pop() ?? ''
    for (const line of lines) {
      const trimmed = line.trim()
      if (!trimmed.startsWith('data:')) continue
      const payload = trimmed.slice(5).trim()
      if (payload === '[DONE]') return
      const delta = JSON.parse(payload).choices?.[0]?.delta?.content
      if (delta) yield delta
    }
  }
}
```

- AbortSignal 贯穿 fetch 与 reader（用户点「停止」立即中断）
- 解析器抽为纯函数 `parseSSEChunk(buffer) => {events, rest}`，便于单测（见专项 ⑥）
- `tool_calls` 流式增量（`delta.tool_calls`）在 Orchestrator 中消费，adapter 层只透传原始 delta：
  为此 `LLMProvider` 契约扩展一个可选方法 `streamChatRaw`（yield 完整 delta JSON），`streamChat` 保持纯文本语义不变

### 3.2 function-calling 编排（Orchestrator.runTask）

沿用 v0.1 的 Plan→Act→Reflect 事件协议（`AgentTraceEvent`），循环结构：

```
1. 组装 messages：[system(角色 systemPrompt)] + history + user(goal)
2. 组装 tools：toolRegistry.listForRole(role) 映射为 OpenAI tools JSON Schema
3. 循环调用 streamChatRaw：
   - delta.tool_calls 非空 → 累积（index 对齐拼接 arguments 分片）
   - 收集完成 → emit tool_call → 执行工具 → emit tool_result → 工具结果以
     { role:'tool', tool_call_id, content: JSON.stringify(result) } 回填 → 继续循环
   - delta.content 非空 → 流式 emit text（打字机节奏沿用 chatStore 现有队列）
   - finish_reason === 'stop' 且无 tool_calls → 跳出
4. emit done
```

**Plan-JSON 降级**（模型不支持 tools 或连续 2 次工具调用失败时）：

- 追加一条 user 指令：要求输出 `{"steps":[{"tool":"queryClassLearning","args":{...}}]}` 纯 JSON
- 解析成功 → 按 v0.1 `MockOrchestrator` 的步骤执行器逐步跑（复用 `runStep` 逻辑，抽到共享模块 `src/harness/agent/stepRunner.ts`）
- 解析失败 → 直接走 `FALLBACK_SCRIPTS[role]`（v0.1 已有），保证任何输入都有响应

**循环护栏**：最多 8 轮工具调用；单工具执行 try/catch，失败以 tool_result 错误摘要回填而非中断。

### 3.3 运行时切换（providerRegistry 改造）

```ts
// 现状：模块加载即固化 → 改为惰性 + 缓存
let cached: { mode: ProviderMode; key: string; providers: Providers } | null = null
export function getProviders(): Providers {
  const s = useSettingsStore.getState()
  const cacheKey = `${s.mode}:${s.apiKey}:${s.baseUrl}:${s.model}`
  if (cached?.key === cacheKey) return cached.providers
  cached = { mode: s.mode, key: cacheKey, providers: buildProviders(s) }
  return cached.providers
}
```

- `chatStore.sendMessage` 改调 `getProviders().agent`
- **回退策略**：API 模式下 runTask 抛错（网络/4xx/5xx）→ emit 一条 reflect 说明「已切换 Mock 剧本」→ 用 MockOrchestrator 重跑同一 goal；连续失败 2 次才向用户报错
- `ACTIVE_MODE` 常量保留为「默认模式」，settingsStore 初始值取自它

- 字段：模式（mock/api 单选）、API 直连 baseUrl（默认 `https://api.deepseek.com/v1`）、model（默认 `deepseek-chat`）、代理地址（可选，见专项 02）、apiKey（password 输入，脱敏显示 `sk-****last4`）

## 五、验收标准

1. **功能**：API 模式下，教师「备一节《摩擦力》公开课教案」、学校管理「生成本月治理简报」、教育局「起草季度质量分析报告」三个场景均产出真实模型生成的 trace 与文档
2. **工具调用**：至少一个场景观察到真实 function-calling（tool_call → tool_result → 继续推理）
3. **降级**：断网 / 错误 key / 模型不返回 tools 三种情况下，均自动回退且用户可感知（reflect 条说明）
4. **中断**：流式过程中点「停止」，请求即时取消（Network 面板可见 canceled），UI 无残留 loading
5. **切换**：mock ↔ api 运行时切换无需刷新页面；切换后缓存正确失效
6. **包体**：`vite build` 后 JS gzip 增量 ≤ 10KB（纯逻辑，无新依赖）

## 六、风险与对策

| 风险 | 对策 |

| DeepSeek 兼容层与 OpenAI 细节差异（如 tool_calls 分片格式） | adapter 层做归一化；联调时用真实响应样本回填单测 |
