# v0.3 专项 ①：角色深化

> 优先级：P1 ｜ 前置：v0.2（DeepSeek 真实接入已交付，工具调用链路稳定）
> 目标：三角色从「通用对话 + 文档」升级为「专属工具界面」——教师试题编辑器、学校预警看板、区域指标看板。

## 一、背景与目标

v0.2 后三角色共享同一工作台布局（trace 流 + Artifact 面板），角色差异仅体现在工具集与剧本。
本专项为每个角色增加一个专属增强界面，让「结构化数据」有结构化呈现：

- 教师：`genQuiz` 产出的试题可结构化编辑（题目/选项/答案/考点），不再只是 Markdown 文本
- 学校管理：`querySchoolStats` 的预警数据以趋势线 + 预警列表联动呈现
- 教育局：`REGION_METRICS` 以多指标卡片 + 环比呈现

## 二、现状与改动文件

| 现状 | 文件 | 改动 |
| --- | --- | --- |
| 工具返回纯文本 summary + payload | `src/harness/agent/tools/index.ts` | `genQuiz` payload 增加结构化题目数组；`querySchoolStats` 增加时序数据 |
| 种子数据无历史序列 | `src/data/seed.ts` | `REGION_METRICS` 增加 `history: {month, value}[]`；新增 `SCHOOL_TREND` |
| 无角色专属界面 | 新增 `src/apps/teacher/`、`src/apps/admin/`、`src/apps/bureau/` | 各角色一个增强面板组件 |
| 工作台按角色渲染 | `src/apps/workbench/Workbench.tsx` | 右栏增加「增强面板」tab（与 Artifact 面板并列） |

## 三、技术方案

### 3.1 结构化试题（教师）

1. `genQuiz` 工具 payload 约定结构（LLM 侧由 function-calling 参数约束 + 解析容错）：

```ts
interface QuizItem {
  type: 'choice' | 'blank' | 'solve'
  stem: string
  options?: string[]        // choice 专用
  answer: string
  knowledgePoint: string
  difficulty: 'easy' | 'medium' | 'hard'
}
```

2. API 模式：Orchestrator 工具结果回填后，模型继续生成；`genQuiz` 的 payload 直接写入
   `quizStore`（新增 `src/stores/quizStore.ts`，LocalStorage 持久化，edustudio: 前缀）。
3. Mock 模式：`genQuiz` 直接返回结构化 payload，行为一致。
4. 编辑器 `src/apps/teacher/QuizEditor.tsx`：列表 + 表单编辑（题目/选项增删/答案/考点/难度），
   保存回写 quizStore；支持「插入到文档」（转 Markdown 追加到当前 Artifact）。

### 3.2 预警看板（学校管理）

1. `querySchoolStats` payload 增加 `trend: {week: string; score: number}[]` 与
   `alerts: {level: 'high'|'mid'; title: string; detail: string}[]`（seed 数据 + Mock 工具同步）。
2. `src/apps/admin/AlertBoard.tsx`：recharts `LineChart`（趋势）+ 预警列表（点击联动高亮对应周）。
3. API 模式下工具返回相同结构（工具层是确定性数据，与 LLM 无关）。

### 3.3 区域指标看板（教育局）

1. `REGION_METRICS` 每项增加 `history: {month: string; value: number}[]`（近 6 期）。
2. `src/apps/bureau/RegionBoard.tsx`：指标卡片（当前值 + 环比箭头）+ 选中指标的趋势图。
3. `queryRegionData` payload 透出 history。

### 3.4 挂载与懒加载

- `Workbench.tsx` 右栏 tabs：`文档` / `增强面板`（按角色：QuizEditor / AlertBoard / RegionBoard）。
- recharts 仅在三个看板组件内 import，且这三个组件经 `React.lazy` + `Suspense` 加载，
  保证主包不引入 recharts（验收以 `vite build` 产物 chunk 分析为准）。

## 四、任务拆解

| # | 任务 | 优先级 | 依赖 |
| --- | --- | --- | --- |

## 五、验收标准

1. 教师角色：让 AI「出 5 道函数题」→ 增强面板出现可编辑试题列表，修改选项后保存，刷新页面数据仍在
2. 学校管理角色：增强面板显示趋势线与预警列表，点击预警项趋势图高亮对应数据点
3. 教育局角色：增强面板显示指标卡片（含环比），切换指标趋势图联动
4. Mock 与 API 双模式行为一致（工具层确定性数据）
5. `vite build`：recharts 位于独立异步 chunk，主包 gzip 增量 ≤ 5KB

## 六、风险与对策

| 风险 | 对策 |
| --- | --- |
| LLM 生成的题目结构不合规 | genQuiz 解析容错：字段缺失回退纯文本 summary，编辑器显示原始文本 |
| recharts 意外进入主包 | 验收步骤 5 强制检查；必要时改用轻量自绘 SVG 图表 |
| 三角色面板代码重复 | 抽公共 `ChartCard` / `MetricCard` 组件到 `src/components/` |
