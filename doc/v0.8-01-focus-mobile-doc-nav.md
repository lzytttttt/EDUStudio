# v0.8 增量优化 · 专注模式移动端操作 / 工作台多文档跳转（交付说明）

> 本专项为 v0.8.0 交付后的小型优化（用户反馈两项），随 v0.8.1 发布。
> 状态：✅ 已完成 · 单测 + tsc 验证通过，无新依赖、零包体增量（纯既有组件内改动）。

## 背景与问题（用户反馈）

1. **专注模式移动端操作逻辑不顺**：v0.7 专注模式的「后台执行」浮动指示器悬浮在简报卡片舞台右上角，
   移动端卡片几乎占满屏宽，指示器直接压在卡片内容上，且与落章位置（`right-5 top-5`）重叠；
   指示器纯展示不可点击，批示过程中想查看后台任务明细只能等全部批示完成后的总结层。
2. **工作台一股脑查看生成结果时，多文档之间跳转不方便**：专注模式批量采纳 → 后台顺序执行 →
   一次产出多份文档；进入工作台「统一处理」时右栏一次只显示一份文档，逐份查看需要反复经
   侧栏「文档」tab（桌面）或「底部标签 → 抽屉 → 文档 tab → 点文档 → 抽屉关闭 → 再开文档面板」
   （移动端）切换，跳转路径过长。

## 改动一：专注模式移动端操作逻辑优化

**问题定位**（`apps/briefing/BriefingPage.tsx`）：

- 指示器 `absolute right-4 top-2` 悬浮于卡片舞台内，移动端遮挡卡片内容与落章区域；
- 指示器无点击行为，任务明细只在批示完成后的 `FocusSummary` 可见。

**实现**：

| 项 | 改动 |
| --- | --- |
| 移动端指示器收进顶栏 | 新增 `focus-indicator-mobile`（`md:hidden`）：Loader 旋转 + 任务计数小胶囊，置于顶栏「工作台」按钮左侧——移动端零遮挡，卡片与落章区域完全让出 |
| 桌面指示器可点击 | 舞台右上角胶囊（`hidden md:flex`，保留 `focus-indicator` testid）由 `div` 改为 `button`，点击打开任务浮层 |
| 后台任务浮层 | 新建 `apps/briefing/FocusTaskSheet.tsx`：任务总数 + 执行中/已完成摘要 + 任务清单（状态图标 + 标题 + 目标 + 状态文字，实时刷新）+「进入工作台查看」；移动端底部贴边弹出（`items-end`），桌面居中；状态元数据复用 `FocusSummary` 导出的 `STATUS_META` / `StatusIcon` |
| 总结层移动端适配 | `FocusSummary` 底部双按钮改 `flex-col-reverse sm:flex-row` 纵向堆叠（小屏并排易溢出），按钮 `w-full sm:w-auto` |

**交互逻辑**：批示过程中（任意端）点击指示器 → 浮层实时展示队列状态；浮层内可直接「进入工作台查看」，
不必等批示完成；批示完成后仍由 `FocusSummary` 承担统一处理入口，浮层作为过程中的补充。

## 改动二：工作台多文档跳转

**问题定位**（`apps/artifacts/ArtifactPanel.tsx`）：一次只渲染 `activeId` 对应文档，
切换文档必须经侧栏/抽屉，移动端路径尤其长。

**实现**（右栏头部文档切换器，桌面常驻栏与移动端抽屉共用，一处改动两端受益）：

| 项 | 改动 |
| --- | --- |
| 上一份/下一份 | `docs.length > 1` 时头部左侧显示 ◀/▶（`doc-switch-prev/next`），边界禁用；旁边 `n/m` 位置指示（tabular-nums） |
| 文档清单下拉 | 标题区变为可点击（`doc-list-btn`，带展开箭头），展开 `doc-list-panel`：全部文档列表（标题 + 类型 + 时间），当前项高亮 + 对勾，**生成中的文档标注「生成中」**（专注模式批量生成场景可一眼分辨哪些已就绪）；点击直达切换并收起 |
| 单文档回退 | 仅一份文档时保持原纯展示标题，不出现切换控件 |

**安全性**：编辑态切换文档无丢失风险——`updateContent` 即时写 store 并持久化，切换仅改 `activeId`。
