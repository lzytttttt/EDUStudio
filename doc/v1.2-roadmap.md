## 0. 一句话与版本定位

**一句话：不搬 Director 的代码，也不重写旧功能。新增一层可擦除的「前端接口契约（Studio Contracts）+ 薄适配层（Studio Bridge）」，让旧 store 继续做唯一事实源、让 Director 降级为「事找人」的视图与编排器；用双轨影子发布把教师默认首页从简报切到战情台，全程可一键回滚。**

v1.0/v1.1 刻意把总指挥模式做成独立 lazy chunk + `?v1=1` 直达（`src/App.tsx:13`、`src/App.tsx:96-108`、`src/lib/directorEntry.ts:7-9`、`doc/v1.1-roadmap.md:35-36`）。这让原型在**不触碰旧流程**的前提下跑通，但也让两套产品在五个层面平行（见 §1.2）。v1.2 的任务不是「合并代码」，而是**合并产品**：用户看到的是一套导航、一套通知、一套交付物；代码上仍然是可独立加载的视图 + 可回滚的开关。

### 本版成功的唯一判据（现场 7 条，逐条可演）

1. 教师一句话委托 → 计划确认 → **真实执行**（无 key / 断网时 100% 回退 Mock 且角标可见）→ 交付物出现在旧「文档」面板，可导出 docx、可分享、可自评；
2. 简报采纳的卡片与总指挥的决策卡**同源**：采纳后战情台出现同一条待办，不出现两套计数；
3. 旧的登录 → 简报 → 工作台全链路仍可走通，既有 35 条 E2E（旧 23 + 总指挥 12）与 7 张视觉基线不回归；
4. 任务跑到一半刷新：`paused` 可继续、不重复 feed、决策与授权保留；
5. 审批门与 Loom checkpoint 在 UI 上是**同一种决策卡**，通过一次只产生一个回执；
6. 移动端只有**一套**底部导航（不出现旧 tabbar 与 Director dock 打架），1440/390 两档走查通过；
7. 包体：主 chunk **≤120KB 不放宽**、全部 JS 按实测重校、零新运行时依赖。

## 2. 融合设计（问题①：怎么结合）

### 2.1 四条融合原则

1. **旧 store 是唯一事实源**：会话、文档、记忆、技能、任务链、通知仍由旧 store 拥有；Director 只持有「编排态」（mission / decision / autonomy / guide）。
2. **Director 是视图 + 编排器，不是第二套数据模型**：`DecisionItem` 改为派生（v1.0 D6 原则「战情台是派生视图」，`doc/v1.0-roadmap.md:383`），输入来自 mission 状态 + 简报决策 + 任务链 + 通知。
3. **能力复用走内核，不搬 UI**：真执行复用 `AgentProvider`（`src/harness/types.ts:202-213`）；交付物复用 `artifactStore` + `exportDoc` + `share` + `Evaluator`；记忆/技能复用 `MemoryProvider` / `skillStore`，只加 Agent 命名空间。
4. **全部新增接口可擦除、可回滚**：主 chunk 只放「类型 + 事件总线 + 路由表」；Director 视图与适配层继续懒加载；每个能力都有 feature 开关（§3.9）。

### 2.2 目标信息架构：一套壳、两个工作区、一份共享资产

```
┌───────────────────────────────── 统一外壳 AppShell ─────────────────────────────────┐
│ 顶栏：[品牌] [工作区切换：总指挥 ⇄ 经典] [一句话输入 IntentBar]   [通知][设置][身份]  │
├──────────────┬──────────────────────────────────────────────┬──────────────────────┤
│ 左侧导航      │                  中栏 SurfaceHost             │  右侧上下文面板       │
│              │                                              │                      │
│ 总指挥工作区  │  战情台 Inbox    （首页 · 事找人）            │  文档（含作战包/溯源）│
│  战情/作战/战队│  作战室 Mission  （计划/动态流/审批门/作战包） │  角色工作台           │
│  ───────────  │  战队 Team      （成员/授权/周报）            │  下发任务链           │
│ 经典工作区    │  ── 或 ──                                     │  团队（只读摘要）     │
│  任务/收藏/   │  对话 Chat / 空间任务台 Loom                  │                      │
│  文档/技能    │                                              │                      │
│  ───────────  │                                              │                      │
│ 最近任务列表  │                                              │                      │
├──────────────┴──────────────────────────────────────────────┴──────────────────────┤
│ 共享资产：artifactStore（文档/版本/分享/导出）· memoryStore（L2/L3）· skillStore      │
│           notificationStore（收件箱）· taskFlowStore（下发/回执）· SourceProvider     │
└─────────────────────────────────────────────────────────────────────────────────────┘
```

- **工作区切换是一级导航**：桌面放左侧导航顶部的分段控件；移动端放顶栏图标（底部标签栏只显示当前工作区的 3 个主去处，避免 3+3 打架）。
- **总指挥工作区**：保留现有三屏信息架构（战情台 / 作战室 / 战队），但去掉自绘顶栏与固定 dock——改为工作区内的分段标签/移动底部标签。
- **经典工作区**：现有三栏工作台原样保留（左任务、中对话/Loom、右文档/看板/下发）。
- **右侧上下文面板共享**：文档面板新增「作战包」分组与溯源 chip；新增「团队」tab（**只读摘要**：成员状态 / 待批准数，授权编辑只在战队页）；旧 tab 不动。

### 2.3 九个结合面（每个都给「现状 → v1.2 做法 → 用户可见变化 → 接口」）

#### F1 简报 ↔ 战情台

- **现状**：简报是登录后首页（`src/App.tsx:100-101`）；采纳卡片走「一卡一任务」会话 + Loom 节点（`src/apps/briefing/BriefingPage.tsx:230-259`、`src/stores/chatStore.ts:121-135`），与 Director 无关。
- **v1.2 做法**：战情台 = 默认首页；简报卡流降级为战情台底部「今日发现」折叠区（可展开、可按 ↑ 收藏，保留落章/滑卡动效）；采纳仍走旧路径（会话 + Loom 节点），同时通过 `StudioBus` 发出 `card.accepted`，由 inbox 派生出一条「已代办」记录；卡片新增次动作「交给战队」→ 进入 mission intake（带出卡片结构化约束）。
- **用户可见**：采纳后不再「跳去工作台」——默认留在战情台看到「已交给战队/已建任务」的回执；想看细节再点开。

## 3. 前端接口设计（问题②：UI 前端接口怎么设计）

> 设计目标：**跨工作区/跨 chunk 只共享契约，不共享实现**。主 chunk 只放「类型 + 事件总线 + 路由表 + 开关」四样小东西（预计 gzip +2–3KB，由 §3.10 的腾挪提供余量）；所有旧 store 与 Director 视图之间通过端口（§3.5）与事件（§3.4）通信，接口实现由懒加载的 bridge 在 Director chunk 内注册。

### 3.1 五层接口与 chunk 边界

```
┌──────────────────────────── 主 chunk（index-*.js，≤120KB 不放宽）────────────────────────────┐
│ ① 契约 src/studio/contracts.ts：RouteState / WorkTarget / Navigator / StudioEvent / 类型映射  │
│ ② 运行时 src/studio/{bus,navigator,flags,inbox,projection}.ts（极薄，无业务依赖）        │
│ ③ 外壳 src/shell/{ShellLayout,SurfaceHost,WorkspaceSwitcher}.tsx + 旧三栏组件               │
│ ④ 旧事实源 stores/*、harness/providers（不感知 Director）                                   │
├───────────────────────────────────┬─────────────────────────────────────────────────────────┤
│ lazy：Director chunk（现 33.9KB）  │ lazy：LoomPanel / QuizEditor / AlertBoard / RegionBoard / │
│ ⑤ CommandCenter + 三视图           │ TaskFlowBoard / ShareView / BriefingPage（M0 腾挪）       │
│ ⑥ bridge/ports（实现①的接口）      │                                                         │
│ ⑦ harness/team/{runner,concurrency}│                                                         │
└───────────────────────────────────┴─────────────────────────────────────────────────────────┘
         ⑤⑥⑦ ──依赖接口──▶ ① ◀──注册实现── ⑥ ──调用──▶ ④（旧 store / providers）
```

**四条硬规则（写成测试，§3.10）**：

1. **主 chunk 不得静态 import Director 模块**（`apps/director`、`harness/director`、`harness/team`、`stores/missionStore`）；只允许 `import type`（类型擦除，编译后 0 字节）。
2. **Director 不得静态 import 旧 store 的「写」路径**：需要写旧 store 时，必须经 `DirectorPorts`（bridge 里实现，便于测试替身与审计）。
3. **跨域通信只走 `StudioBus`**：禁止在 `AppShell`/`Sidebar` 里直接读 Director store；禁止用 `window` 自定义事件（现有 flush 钩子是历史例外，v1.2 保留但不再新增）。**唯一例外**：主 chunk 可读 `studio/projection.ts` 的 `StudioDigest`（只读派生：计数 + 一行摘要，≤1KB，事件驱动更新、持久化在 `settings.studio.digest`），不得读实体/正文；该例外写入边界测试白名单。
4. **新增懒加载模块不改变首屏语义**：懒加载失败要有降级（skeleton + 错误边界回退到经典工作区）。

### 3.2 导航接口（Route / Navigator / 深链）

**核心契约**（完整 TS 见附录 A）：

```ts
// src/studio/contracts.ts
export type WorkspaceId = 'director' | 'classic'
export type DirectorView = 'inbox' | 'mission' | 'team'
export type ClassicView = 'chat' | 'loom'
export type RightTab = 'doc' | 'board' | 'flow' | 'team'

export type WorkTarget =
  | { kind: 'inbox' }
  | { kind: 'mission'; id?: string; taskId?: string }
  | { kind: 'team'; agentId?: DirectorAgentId }
  | { kind: 'chat'; id?: string }
  | { kind: 'loom'; id?: string }
  | { kind: 'doc'; id: string }
  | { kind: 'decision'; id: string }
  | { kind: 'briefing'; cardId?: string }
  | { kind: 'board'; role: RoleId }

export interface RouteState {
  workspace: WorkspaceId
  directorView: DirectorView
  classicView: ClassicView
  rightTab: RightTab
  target: WorkTarget | null
}

export interface Navigator {
  open(target: WorkTarget, opts?: { replace?: boolean; source?: 'user' | 'system' | 'deep-link' }): void
  go(route: Partial<RouteState>, opts?: { replace?: boolean }): void
  back(): void
  canBack(): boolean
}
```

**深链协议（URL 查询参数，不新增路由库）**：

| 参数 | 含义 | 示例 | 兼容 |
| --- | --- | --- | --- |
| `v2=1` | 启用统一工作区（影子期） | `/?v2=1&view=inbox` | M4 后默认 |
| `legacy=1` | 回滚开关：单独使用 = 经典工作区；与 `v1=1` 联用 = 旧 Director 整屏（M4 起只读） | `/?legacy=1`、`/?v1=1&legacy=1` | 回滚 |
| `v1=1` | 兼容别名：影子期指旧整屏；M4 起映射到 `v2` 的战情台（旧整屏走 `v1=1&legacy=1`） | `/?v1=1&tour=0` | 保留至 v1.3 |
| `view` | `inbox` / `mission` / `team` / `chat` / `loom` / `briefing` | `&view=mission` | 新 |
| `id` / `task` / `agent` | 目标实体 id | `&view=mission&id=m-1` | 新 |
| `tab` | 右栏 `doc`/`board`/`flow`/`team` | `&tab=doc` | 新 |
| `tour` | 引导 `1` 强制 / `0` 关闭 | `&tour=1` | 沿用（`src/apps/director/DirectorApp.tsx:64-72`） |
| `mission=exam_loop` | 演示兜底种计划 | 沿用 | 沿用（`:74-91`） |
| `exec` | `mock` 强制演示执行 | `&exec=mock` | 新（替代 `?llm=0` 的执行侧语义，二者都保留） |

**History 语义**：每次 `Navigator.open` 且 `source!=='system'` 时 `pushState({route})`；`popstate` 反序列化回 `routeStore`；`system` 跳转（如执行完成自动切作战室）用 `replaceState`，避免污染返回栈。`#share=` 仍然最高优先、不参与路由（`src/App.tsx:16-24`）。

**验收点**：`(route, URL, history)` 三态一致性矩阵单测（≥12 例）：直接深链、刷新保持、返回逐级、非法参数回默认、分享优先、旧 `?v1=1` 兼容。

### 3.3 外壳插槽接口（Shell / SurfaceHost / 共享 chrome）

把「整屏应用」拆成「外壳 + 可注册的视图」。外壳不再认识 Director 细节，Director 也不再绘制自己的顶栏/dock。

**事件目录（生产者 → 消费者）**：

| 事件 | 生产者 | 消费者 | 用途 |
| --- | --- | --- | --- |
| `card.accepted` | 简报页（旧代码，新增一行 emit） | inbox / mission intake / memory | 派生「已代办」+ 可「交给战队」 |
| `intent.submitted` | IntentBar（三个入口共用） | directorStore / inbox | 一句话委托的唯一入口 |
| `mission.*` / `gate.*` | runner / missionStore / Loom runner | 战情台、侧栏角标、通知、Loom 画布 | 单一在办状态；**审批门只发 `gate.*` 一种**，按 `gateId` 去重，一次解决只发一次 |
| `artifact.published` | deliverables 端口 | 文档面板、Sidebar 文档 tab、通知 | 交付物出现即可见 |
| `agent.feedback` | 战队/审批动作 | memory、skill、trust 计数 | 学习闭环 |
| `notice.push` | 各来源 | 收件箱、角标 | 一个收件箱 |
| `navigation.request` | 旧页面按钮 / 通知点击 | Navigator | 深链跳转不产生循环 import |

**总线纪律**：同步派发、单个 handler 异常隔离（try/catch + console.error）；handler 必须幂等；事件负载不可变、只带 id 与事实（不传 store 对象/函数）；同一 tick 内重复事件去重由消费者负责（沿用 v0.9.3 in-flight 去重先例）。**审批门只有一个事件源**：mission gate 与 Loom checkpoint 都发 `gate.waiting`（`ApprovalGate.source` 区分），`resolveGate` 成功后只发一次 `gate.resolved`；收件箱与角标以 `gateId` 去重，保证「同一件事不会两处各点一次」。

### 3.7 状态与持久化接口（v1 兼容 → v2 收口）

**双轨兼容策略（关键）**：M0–M3 期间旧 `DirectorApp` 与旧工作台流程仍要能跑，因此过渡期持久化**严格保持 v1 形状**：`schemaVersion: 1`、`MissionState.status` 仍为 6 值（`src/stores/directorPersistence.ts:49,202-204` 的白名单不动）、`decisions` 仍是 v1 `DecisionItem`（`:245-283` 的 sanitize 不动）。新增信息全部放进**新增 optional 字段**（`execution` / `intake` / `artifactIds` / `stale`），并由同一 release 内的 `toPersistedDirector`（`:125-151`）与 sanitize 函数显式写出、读回时保留；旧整屏视图只读它认识的字段。**不把 `partial/failed` 写进 `MissionState.status`**——真执行结果放 `execution.outcome: 'done' | 'partial' | 'failed' | 'cancelled'`；`MissionStatus` 扩 enum 只在 M4 升 `schemaVersion: 2` 时做（新增 `partial/failed` 两值）。M4 同时下线 v1 持久化**恢复路径**（旧数据自动迁移），但旧整屏**只读视图**在 `?v1=1&legacy=1` 下保留至 v1.3（§5.1）。
注意：「旧读取器」仅指回滚到 v1.1 二进制的场景（只认 `schemaVersion: 1` 且 `MISSION_STATUSES` 白名单），因此二进制回滚必须先导出备份（§5.3）；同一 release 内不受此限。**过渡期必须补 `v1 ↔ v1plus` 往返单测**（写入 → 读回 → 新字段保留 → 旧视图可读 → 旧字段不丢）。

**主 chunk 余量来源（M0 必做，先腾后加）**：当前主 chunk 119.5/120KB，只剩 0.5KB。M0 把 `BriefingPage`（34,035B 源码，静态 import 于 `src/App.tsx:4`）与 `ShareView`（18,659B 源码，静态 import 于 `src/App.tsx:6`）改为 `React.lazy`。**注意 BriefingPage 是教师登录默认落点**（`src/stores/authStore.ts:24-27`），这不是纯收益，而是「用一次懒 chunk 加载换主 chunk 预算」：首屏多一次异步加载，需纳入 Lighthouse/E2E 计时与降级验证；`ShareView` 只在分享路由出现，是纯收益。预计释放 **4–8KB gzip（以 M0 实测为准）**；同时必须计入下列新增成本，预算账才闭合：契约/总线/路由（+2–3KB）、五原语提取到主 chunk（+1–2KB）、ShellLayout/WorkspaceSwitcher/IntentBar（+2–4KB）——因此 **M0 先实测再定 M1 形态，主 chunk 目标 ≤118KB（≥2KB 余量）**。**不抬 120KB 阈值**（`scripts/budget.mjs:37` 纪律）；全部 JS 不因懒加载下降（总量按实测重校）。

| 闸门 | v1.2 目标 | 说明 |
| --- | --- | --- |
| 主 chunk | ≤120KB（不放宽） | M0 腾挪后目标 ≤118KB（≥2KB 余量），M1–M2 增长仍在预算内 |

## 4. 执行层融合（真执行，v1.2 的另一条主线）

### 4.1 目标与边界

- **目标**：mission 的每个任务由真实 `AgentProvider` 执行（API 模式下真模型 + function-calling + 工具；Mock 模式下按 Agent 剧本产出），产物写入 `artifactStore`，门与校验走真实规则；「真执行」与「演示」用角标明确区分。
- **边界**：不改 `chatStore` 主循环（`doc/v1.1-roadmap.md:482`）；不把 mission 塞进 chat 单飞；不引入新依赖；真执行只在 Director chunk 内，主 chunk 不感知。

### 4.3 Orchestrator agent-scoped 扩展（缺省字节级不变）

- `Orchestrator.runTask`：当 `input.agent` 存在时，system prompt 由 `AgentSpec` 组装（baseRole 语气 + 岗位职责 + notDo + 记忆/技能命名空间），工具白名单 = `AgentSpec.tools ∩ toolRegistry.listForRole(baseRole)`（沿用 `src/harness/agent/ToolRegistry.ts:16` 与 `tools/index.ts:299-333` 的注册表）；不存在时走旧分支，**逐字节不变**（`doc/v1.0-research/02-swarm-architecture.md:33,68` 先例）。

### 4.4 Gate 与 Loom checkpoint 统一契约

```ts
export interface ApprovalGate {
  gateId: string                          // Mission GateId 或 Loom checkpoint id
  missionId?: string
  taskId?: string
  source: 'mission' | 'loom'
  title: string
  ownerAgentId?: DirectorAgentId
  requiredAction: 'approve' | 'edit' | 'continue'
  /** 门后动作是否对外/不可逆（硬门：永不自动放行） */
  sensitive: boolean
  editableTarget?: ArtifactRef
  evidence?: { citations: Citation[]; verification: VerifySummary }
}
```

- mission gate（`GateId`，`src/harness/director/types.ts:34`）与 Loom checkpoint（`src/harness/loom/runner.ts:185-189,231-239`）都投影为 `ApprovalGate`，进同一个收件箱；
- `resolveGate(gateId, action)` 是唯一出口：mission 更新 `mission.gate`，Loom 更新节点状态；**同一 gateId 只允许一次解决**（幂等，事件去重）；
- 硬门（对外发送/成绩公开/处分心理）恒 `sensitive: true`，授权 L0–L3 不可上调（`doc/v1.0-roadmap.md:297-305`）。

### 4.5 交付物发布链路

```
runner 产出（Markdown + citations）
  → evidence.verify（verifyCitations：统计型数字 100% 可溯源，结构性数字白名单）
  → deliverables.publish（artifactStore.createPlaceholder → 内容 → finalize）
  → provenance 注入（missionId / taskId / agentId / citations / refs）
  → StudioBus.artifact.published
  → 文档面板「作战包」分组 + 未读点 + 通知（不抢焦点）
  → 用户：编辑（版本历史）→ 导出 docx/xlsx/pdf → 分享短链 → 自评（Evaluator）
```

**失败与降级**：校验不通过 → 不发布正文，标「待核」并回退为建议（不静默改数字）；artifactStore 写失败 → 保留内存草稿 + toast；导出失败 → 提示可复制 Markdown。

### 4.6 失败降级矩阵

| --- | --- | --- | --- |

| 断网 / 5xx | 同上，不重试到死 | 同上 | 同上 |
