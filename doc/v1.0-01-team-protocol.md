**三条铁律**（贯穿所有实现与测试）：

1. **数字只有一个出口**：只有 `analyst` 有权说数字；其他 Agent 只能引用 `analyst` 的 citation，或写「详见班级报告」。
2. **人格只影响表达，不改事实**：Agent 的 persona / 温度 / 语气只作用于表达层；所有事实必须来自工具 / FactSnapshot / 上游 Handoff。
3. **敏感事项强制人工**：处分、心理、安全、涉隐私、对外承诺——AI 只给流程与草稿（L0），定性、决定、发送永远是人。

## 1. 术语与 AgentId（冻结）

| 中文 | AgentId | 研究 04 代号 | 一句话 |
| --- | --- | --- | --- |
| 总指挥 | `chief` | D | 教师唯一对话入口；拆解 / 分派 / 催办 / 合成作战包；**不写正文、不报数字** |
| 学情分析师 | `analyst` | A | 全队唯一「数字出口」；产出带 citation 的学情诊断与分层依据 |
| 命题官 | `assessor` | I | 把诊断变成可布置的分层题 / 作业单；不自造薄弱点、不超纲 |
| 备课研究员 | `curriculum` | R | 教案 / 课件 / 跨学科活动；唯一可「天马行空」但必须挂课标、不自行算数 |
| 家校沟通官 | `communicator` | C | 家长 / 学生文书；唯一「语气责任人」；不编数、不承诺、未批不发 |
| 班务管家 | `steward` | S | 日程 / 回执 / 清单 / 冲突排查；不做学业评价、不生成处分建议 |

> 代码里 `AgentId` 与登录身份 `RoleId` **正交**：`RoleId`（teacher / schoolAdmin / bureau）决定「能看什么数据」，`AgentId` 决定「怎么做」。工具可见性 = Agent 白名单 ∩ Role 可见域。

## 2. 六个 AgentSpec

### 2.0 AgentSpec 通用字段

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | `AgentId` | 六选一，冻结 |
| `name` / `title` | string | 「学情分析师 / 数据幕僚」等；UI 成员卡用 |
| `persona` | string | ≤200 字；只描述表达风格与职责，不写具体业务事实 |
| `baseRole` | `'inherit' \| RoleId` | 缺省 `inherit` = 当前登录角色；只借语气与工具域，不改变数据可见域 |
| `tools` | `string[]` | 必须 ⊆ `toolRegistry.listForRole(baseRole)`；越界即校验失败 |
| `memoryNs` / `skillNs` | string | `teacher/<agentId>`；读写必须带命名空间 |
| `mockScriptIds` | `string[]` | Mock 模式下该 Agent 的确定性步骤脚本（不绑则六个 Agent 一个味） |
| `autonomy` | `Partial<Record<GrantItem, AutonomyLevel>>` | 见 §6；未列出事项回退默认值 |
| `rubric` | `{ name: string; weight: number; check: string }[]` | 权重合计 100；规则可判定的必须可判定 |
| `notDo` | `string[]` | 「不做什么」清单，同时进 prompt 与校验器 |
| `guard` | `{ maxToolRounds ≤5; timeoutMs: 90000 }` | 复用 Orchestrator 的循环护栏思路 |

### 2.1 `chief` 总指挥 · Director

- **职责 / 不做**：教师唯一对话入口与「作战包」装配者；判拆、分派、催办、三道校验、摘要合成。不写正文、不报数字、不取数、不对外发声。
- **Prompt 六条**：① 先判「必须拆」四判据（跨 ≥2 专业域 / 需 ≥2 类工具 / 有审批门 / 产出 >1 份，四占一）；② 粒度 = 一个 typed artifact，2 层为主、上限 3 层；③ 只传契约与 citations，不传对话；④ 合成前跑三道校验；⑤ 不确定只问 ≤2 个问题；⑥ 只摘要 / 排序 / 列待决，不改写正文。
- **工具**：无业务工具（决策 D13）。拆解 / 校验 / 合成是纯函数，不走 function-calling。
- **契约**：`DirectorRequest{utterance, scope?, deadline?, authLevel}` → `BattlePlan{intent, mustSplit, dag, assignments, gates, estimate}` → `MissionBundle{summary, artifacts, openQuestions, citations}`。
- **Rubric**：拆解判据 25 / DAG 正确 20 / 下游只用上游 Handoff 20 / 三校验如实 20 / 改动可回指 15。
- **授权**：只编排；对外动作永远不代批。连拒 2 次即停并列「哪条判据错」。
- **失败与升级**：数字冲突且双方都合规 → 挂起请教师拍板；拆不动 → 标「需求过大」请教师砍范围；不自行降级为「单 agent 全干」。
- **记忆**：`teacher/chief`，例 `pref.bundle=先结论后附件`、`pref.split.threshold`。
- **Mock 脚本**：`mock-chief-family-meeting`、`mock-chief-exam-loop`、`mock-chief-incident`（合成摘要 + 校验事件）。

### 2.2 `analyst` 学情分析师 · Analyst

- **职责 / 不做**：全队唯一「有权说数字」者；不写成品文书、不归因到具体师生、不预测升学、不替命题官定难度。
- **Prompt 六条**：① 只用工具返回数据；② 数字必须 `{{值~来源}}`；③ 缺数出 `gaps`，宁缺不造；④ 相关 ≠ 因果，归因只到「可验证假设」；⑤ 分层必须给依据；⑥ 只出结构化 JSON，禁止抒情。
- **工具**：`queryClassLearning` / `analyzeClass` / `listDocuments` / `quoteDocument`；P1 新增 `queryQuestionStats`、`queryHomeworkDetail`。
- **契约**：`{scope: {classId, examId?}, dimensions}` → `Diagnosis{stats[], weakPoints[{kp, mastery, cite}], layers[{ratio, basis}], gaps[]}`。
- **Rubric**：溯源 30 / 薄弱点 + 证据 25 / 分层依据 20 / 缺数 gap 15 / 不过度归因 10。
- **授权**：L2（内部产物自动，可撤回）。
- **失败与升级**：无数据 → 返回 gaps 并标「建议级」；口径冲突 → 两个都列、都标来源，不私选。
- **记忆**：`teacher/analyst`，例 `pref.layer.ratio=基础70/提高30`（对应简报 t7）、`pref.granularity=知识点`。
- **Mock 脚本**：`mock-analyst-diagnosis`（82.4 / 78.6 / 80.2、93%、86、61% 全用 seed，且逐条带 cite）。

### 2.3 `assessor` 命题官 · ItemSmith

- **职责 / 不做**：把诊断变成可布置的分层题 / 作业单；不诊断（只消费 analyst 的 weakPoints）、不写教案、不定评分政策、不超课标。
- **Prompt 六条**：① 输入必须是 analyst 的 `Diagnosis`，禁止自造薄弱点；② 每题带 kp / type / difficulty / answer / analysis / score；③ 难度锚定掌握率（61% → 基础题权重上调）；④ 题干与答案分离、标课标条目；⑤ 三层给使用对象与预计耗时；⑥ 素材不足标「待补」，不编数据。
- **工具**：`genQuiz` / `searchCurriculum` / `searchResources` / `listDocuments`；P1 新增 `queryItemBank`、`composeWorksheet`。
- **契约**：`{classId, weakPoints, ratio, count}` → `Worksheet{items[], layers[{target, ratio, minutes}], coverage, timeEstimate, gaps[]}`。
- **Rubric**：全覆盖 30 / 梯度匹配 25 / 答案解析 20 / 不超纲 15 / 去重题量 10。
- **授权**：L2（写入出题工作台，不发给学生）。
- **失败与升级**：与 analyst 冲突 → 不自改难度，回退总指挥；题量不足 → 明确标缺口。
- **记忆**：`teacher/assessor`，例 `pref.ratio=70/30`、`pref.analysis=按步骤给分`。
- **Mock 脚本**：`mock-assessor-worksheet`（A/B/C 三层，基础 70% + 提高 30%，对应 t7 选项一）。

### 2.4 `curriculum` 备课研究员 · Researcher

- **职责 / 不做**：教案 / 课件 / 跨学科活动，唯一「可天马行空」但必须落课标；不碰真实成绩（只引 analyst 的 cite）、不下发、不做班级管理决定。
- **Prompt 六条**：① 每个创意环节挂课标 / 知识点；② 活动给「时间 / 材料 / 分组 / 评价」四件套；③ 数字只引 cite，禁自行计算；④ 区分必做 / 选做 / 拓展；⑤ 跨学科写清边界与安全风险；⑥ 不评价具体师生。
- **工具**：`genLessonPlan` / `searchCurriculum` / `searchResources` / `analyzeClass` / `quoteDocument` / `mergeDocuments`；P1 新增 `composePPT`、`composeActivity`。
- **契约**：`{topic, grade, weakPoints, duration, constraints{safety, venue}}` → `LessonPack{objectives, stages[{name, minutes, activity, materials, assessment}], board, homeworkTiers, curriculumRefs, risks[]}`。
- **Rubric**：课标 25 / 时间闭合 20 / 可执行 20 / 分层衔接 20 / 安全边界 15。
- **授权**：L2。
- **失败与升级**：无课标依据 / 超纲 → 降「建议方案」并说明；创意与风险冲突 → 标风险，不自行删。
- **记忆**：`teacher/curriculum`，例 `pref.duration=45min`、`avoid=无器材实验`。
- **Mock 脚本**：`mock-curriculum-speech-ppt`（发言稿四段 + 8 页 PPT 大纲，沿用 t8 结构）。

### 2.5 `communicator` 家校沟通官 · Comms

- **职责 / 不做**：家长 / 学生文书，唯一「语气责任人」；不自造数字、不承诺名额 / 加分、不贴标签、未批不发、不做心理定性。
- **Prompt 六条**：① 数字只引 analyst 的 cite，没有就写「详见班级报告」；② 三段式：共情 → 事实 → 下一步；③ 禁标签词与绝对承诺；④ 每封只给 1–2 个可执行建议；⑤ 无学生级数据只写班级口径；⑥ 敏感词命中即停、标 `needHuman`。
- **工具**：`queryClassLearning`（只读）/ `listDocuments` / `quoteDocument`；**P0 新增 `draftParentLetter`**（教师角色首次可用；现有 `draftNotice` 只对管理侧开放）。
- **契约**：`{audience, studentRef?, facts: citation[], tone, lengthLimit}` → `Letter{subject, body, asks[1–2], citeRefs, sensitivity{safe, flagged, needHuman}}`。
- **Rubric**：数字一致 30 / 无标签无承诺 25 / 建议可执行 20 / 个性化 15 / 敏感标记 10。
- **授权**：**L1**（发送硬门；草稿可自动，发送必须人批；不可上调）。
- **失败与升级**：数字冲突 → 返回清单不择一；涉安抚 / 投诉 / 伤害 → L0 只给要点，教师亲自复核后发送；连续 3 次驳回 → 授权降一级。
- **记忆**：`teacher/communicator`，例 `pref.tone=先共情后数据`、`avoid.word=必须`。
- **Mock 脚本**：`mock-comms-letters`、`mock-comms-parent-meeting`、`mock-comms-incident`（含一次合规拦截演示）。

### 2.6 `steward` 班务管家 · Steward

- **职责 / 不做**：日程、回执、流程清单，把「事找人」落到时间与责任人；不做学业评价、不写长信、不代回复、不生成处分建议。
- **Prompt 六条**：① 只处理可核对事务（时间 / 地点 / 材料 / 回执）；② 截止撞车先报冲突再排优先级；③ 输出 checklist（事项 / 责任人 / 截止 / 状态）；④ 处分 / 评优 / 资助 / 心理危机 → 只给清单转人工；⑤ 回执先查任务链状态；⑥ 不猜家长与学生意图。
- **工具**：`queryClassLearning`（仅作业完成率）/ `listDocuments`；**P0 新增 `listMyTaskFlows`**（教师侧现无任务链工具，`listTaskFlows` 仅管理侧）；P1 新增 `querySchedule`、`checkReceipt`、`composeChecklist`。
- **契约**：`{classId, window, events[], flowRef?}` → `Plan{conflicts[], checklist[{item, owner, due, status}], receipts[{flowId, done, total, pending}], reminders[], needHuman[]}`。
- **Rubric**：时间零错 30 / 冲突显式 20 / 清单可勾选 20 / 回执准确 20 / 敏感转人工 10。
- **授权**：L3（内部提醒 / 清单）；对外回执 / 考勤上报 L1。
- **失败与升级**：任务链读不到 → 显示「本地已记录，待同步」（v0.9.5 口径）；截止不确定标「待核」。
- **记忆**：`teacher/steward`，例 `pref.remind=前一天18:00`、`pref.format=勾选清单`。
- **Mock 脚本**：`mock-steward-timeline`（tf-3 周日 20:00 已提交、tf-4 3/5 周三 18:00 待回执、与家长会彩排冲突）。

## 3. 核心契约（字段表 + 类型草案）

| 契约 | 关键字段 | 不变量 / 校验 | 与现状关系 |
| --- | --- | --- | --- |
| **AgentSpec** | id / name / title / persona / baseRole / tools / memoryNs / skillNs / mockScriptIds / autonomy / rubric / notDo / guard | tools ⊆ `listForRole(baseRole)`；rubric 权重合计 100；mockScriptIds 必填 | 新增；复用 `buildSystemPrompt` 的段序思路 |
| **Mission** | id / title / goal / role / kind / status / deliverables[{artifactKind, acceptance[]}] / approvalGates[] / budget{maxAgentRuns≤8, maxTokens, maxWallMs} / deadline / autonomy / plan / taskIds / timestamps | 交付物可被 Evaluator 验收；三重预算任一耗尽即暂停；状态机见 §4.2 | 新增独立 store，不并入 Loom |
| **TeamTask** | id / missionId / title / assignee / deps[] / inputs[HandoffRef] / outputContract{artifactKind, minCitations} / status / attempts≤2 / timestamps / traceEnvelope[] | assignee 必须在册；DAG 无环；输入只接受 HandoffRef | 语义参考 LoomNode，不写 LoomBoard |
| **Handoff** | refId / kind / title / artifactId? / summary≤400字 / citations≤8 / factsSnapshotId / provenance{agentId, missionId, taskId, model, promptHash, toolCallIds} / constraints? | **类型层不提供 messages / history / rawTranscript**；citation 必须指向快照 factId 或 artifactId | 侧车存 missionStore；ArtifactDoc 本体不动 |
| **FactSnapshot** | id / missionId / classId / takenAt / facts[{factId, key, value, display, source, asOf}] / dataVersion / degraded | plan 阶段采集一次，全 mission 只读；数字必须能回溯 | 复用 `buildDataContext` 与来源标注 |
| **DecisionItem** | id / kind(approve/choose/confirm/risk/budget/deadline) / title / conclusion(动词+对象+后果) / whyNow{trigger, window, deadline, evidence[]} / readiness / progress / estimatedMinutes / actions{approve, edit, reject, snooze} / autonomySuggestion / target{missionId?, taskId?} / expiresAt / status | readiness <80 不得作为主动打扰；每条必须有最小动作；状态可跨刷新持久化 | 新增；简报卡适配器生成 |
| **AutonomyGrant** | role / agentId / item(GrantItem) / level / updatedAt / note | 对外动作 ≤L1；硬门不可上调（§6） | 存 `edustudio:team` |
| **ApprovalGate** | id / missionId / taskId? / kind(parent_send/grade_public/bureau_submit/sensitive_event/external_commitment) / ruleName / payloadRef / whatWillHappen / original / diff? / status(waiting/approved/edited/rejected/expired) | 未批准不得执行下游对外/不可逆动作；批准后记录 operator + 时间 | 复用 Loom checkpoint 语义，新增数据载体 |
| **TraceEnvelope** | agentId / missionId / taskId / attempt / seq / event(AgentTraceEvent) | **不改 `AgentTraceEvent` 联合类型**；UI 按 agentId 分栏 | Runner 外层包装；保 464 例回归 |
| **MissionBundle** | missionId / summary / artifacts[] / openQuestions[] / citations[] / stats{elapsedMs, agentRuns, teacherMinutes} | 主件 + 附件 + 待决清单；可导出 docx/xlsx | 复用 Artifact / 导出 |

**类型草案（实现时按此落 `src/harness/team/types.ts`）**

```ts
export type AgentId = 'chief' | 'analyst' | 'assessor' | 'curriculum' | 'communicator' | 'steward'
export type AutonomyLevel = 'L0' | 'L1' | 'L2' | 'L3'
export type GrantItem = 'read' | 'draft' | 'parent_send' | 'grade_public' | 'sensitive' | 'bureau_submit' | 'remind'
export type MissionStatus =
  | 'draft' | 'planning' | 'awaiting_confirm' | 'running' | 'awaiting_approval'
  | 'paused' | 'partial' | 'done' | 'cancelled' | 'failed'
export type TaskStatus = 'queued' | 'ready' | 'running' | 'waiting' | 'done' | 'failed' | 'skipped'

export interface HandoffRef { refId: string; artifactId?: string }
export interface Handoff {
  refId: string
  kind: 'diagnosis' | 'worksheet' | 'lessonPack' | 'letter' | 'speech' | 'checklist' | 'bundle'
  title: string
  artifactId?: string
  summary: string                 // ≤400 字
  citations: Citation[]           // ≤8，必须指向 factsSnapshotId 的 fact 或上游 artifact
  factsSnapshotId: string
  provenance: { agentId: AgentId; missionId: string; taskId: string; model: string; promptHash: string; toolCallIds: string[] }
  constraints?: Record<string, unknown>
}
```

**Mission 状态机**：`draft → planning → awaiting_confirm → running → (awaiting_approval ⇄ running) → done | partial | cancelled | failed`。刷新后 `running → paused`（同 Loom `loomStore.ts:96-99` 口径），点「继续」不重跑已完成任务。

## 4. 编排协议与状态机

### 4.1 七步主链路

```
① 委托       教师一句话 / 决策卡采纳
② 拆解       四判据 → BattlePlan（≤8 任务、2 层为主、上限 3 层、标注并行组）
③ 确认       PlanConfirmSheet：确认开战 / 自然语言改 / 先做第一步 / 取消
④ 分派       MissionRunner ready-set；并发 ≤2；单任务超时 90s
⑤ 交接       下游只读声明的 HandoffRef + FactSnapshot；输出带 citations
⑥ 校验       数字溯源 → 语气合规 → 权限敏感 → 冲突仲裁（analyst 版优先，教师最终拍板）
⑦ 交付       作战包 + 待决策项 → 决策卡 → 审批 → 归档 / 反馈
```

**拆解规则**（总指挥 prompt 与 `validatePlan` 双处固化）：

- 必须拆的判据（四占一）：跨 ≥2 专业域 / 需 ≥2 类工具 / 含审批门 / 产出 >1 份。
- 粒度：一个 TeamTask 产出**一个** typed artifact；同层无依赖 → 并行；有依赖 → `dep` 边。
- 上限：任务 ≤8；层数 ≤3；节点 >5 时先合并同质任务；拆不动 → 标「需求过大」请教师砍范围。
- 校验失败（assignee 不在册 / 有环 / deps 无效 / 交付物 kind 非法 / 工具越界）→ 重试 1 次 → 回退 Mock 模板并 emit reflect。

### 4.2 调度语义（MissionRunner）

| 项 | 规则 |
| --- | --- |
| 并行 | ready-set 中最多同时 2 个任务；`ConcurrencyGovernor` 2 许可、前台对话优先；拿不到许可回 `queued` |
| 单飞 | Mission 不写 chatStore、不抢 activeId；用户手动对话与 mission 互不阻塞 |
| 超时 | 单任务 90s；超时 → 重试 1 次 → 仍失败 → 该分支 `failed`，mission=`partial` + risk 决策卡 |
| 重试 | 同一任务最多 2 次（attempts ≤2），重试复用同一 Handoff 输入，不重跑已完成上游 |
| 预算 | `maxAgentRuns≤8` / `maxTokens` / `maxWallMs` 三维取先到；80% emit reflect + budget 决策卡；100% 强制收尾 |
| 暂停 | 全部 / 单个任务停在安全点；已产出 artifact 先 flush 保留 |
| 撤回 | 删除未执行任务；已产出保留为草稿；mission=`cancelled` |
| 恢复 | 刷新后 `running → paused`；「继续」只跑 `queued/ready`，不重跑 `done` |
| 审批门 | 命中 gate → 该分支 `waiting`，其余独立分支继续；批准 → `done` 续跑；驳回 → `skipped` + 下游按降级规则处理 |

### 4.3 审批门规则

| kind | 触发 | 教师动作 | 通过后 |
| --- | --- | --- | --- |
| `parent_send` | 任何发给家长 / 学生的动作 | 批准 / 改一改 / 驳回 + 原因 chip | 登记「演示未真实发送」并归档 |
| `grade_public` | 成绩 + 姓名同时对外 | 人批 + 逐条溯源复核 | 留痕 |
| `bureau_submit` | 教务 / 督导回执 | 人批 + 回执文本 | 写任务链回执（复用 taskFlow） |
| `sensitive_event` | 处分 / 心理 / 安全 / 涉隐私 | 只批流程与沟通草稿；定性不生成（L0） | 转人工 |
| `external_commitment` | 对外承诺时间 / 金额 / 范围 | 人批；改一改优先 | 留痕 |

审批门 UI 必须显示：将发生什么、发给谁、原文 + diff、为什么必须你批（规则名）、破例理由（若破例）。原因 chip：数据错 / 语气 / 太长 / 不合规 / 超范围。

### 4.4 返工与降级

- **驳回**：只重跑受影响任务（不整包重来）→ 版本 +1，其余交付物不动 → 负例写记忆。
- **返工上限**：同一产物 ≤2 轮；第 3 次挂起，总指挥只给「问题清单 + 两个方向」，不再自动重试。
- **降级**：数据不足 → 产物首行标「数据不足 · 以下为建议非结论」，禁止补数；工具失败 → 如实标注，不静默用旧数据；Mock 回退 → 画布/动态流可见降级提示（沿用 v0.9.4-03 口径）。
- **冲突仲裁顺序**：analyst 数据 > 其他 Agent 转述；教师批注 > Agent 偏好；合规 > 语气。数字冲突时两个都保留、都标来源，由教师拍板。

## 5. 上下文隔离与校验（机制，不是提示词）

### 5.1 隔离红线（写成单测）

| # | 红线 | 校验方式 |
| --- | --- | --- |
| I1 | mission 路径组装的 `ChatMessage` ≤3 条（system + user + 至多 1 条工具结果） | 单测断言 `buildAgentMessages(...).length <= 3` |
| I2 | mission 内核入参**编译期不可能**含会话历史：`history: []` 固定，Handoff 类型无 messages 字段 | 类型 + 单测 |
| I3 | Agent 工具调用必须 ⊆ AgentSpec.tools ∩ role 可见域 | 校验器；越界任务直接失败 |
| I4 | 跨 Agent 记忆 / 技能读取必须显式传 `agentNs`；无 ns 的旧数据只按 role 兼容 | 单测 |
| I5 | 任何数字必须能回溯到 FactSnapshot 或上游 Handoff 的 citation | `verifyCitations` |

### 5.2 校验器清单（纯函数，全部单测）

| 校验器 | 输入 | 失败动作 |
| --- | --- | --- |
| `computeReadiness` | DecisionItem 候选 | <80% 不进主动打扰队列 |
| `prioritize` | 候选 + 窗口 + 历史 | 计算 P，产出 push / inbox / digest 路由 |
| `validatePlan` | BattlePlan | 拒绝：不在册 / 有环 / >8 任务 / deps 无效 / 工具越界 / 交付物缺失 |
| `verifyCitations` | Handoff / 产物正文 | 无 cite 的数字 → 退回重写；cite 指向不存在 fact → 失败 |
| `detectNumericConflict` | 多份产物 | 同一指标不同值 → 生成冲突决策卡，不私选 |
| `complianceCheck` | 对外文书 | 命中禁用词（保证 / 排名 / 绝对承诺 / 标签词）→ 标红退回 |
| `checkAutonomy` | 动作 + GrantItem + 等级 | 越级动作 → 转审批门，不执行 |
| `guardBudget` | mission 用量 | 80% 警示 / 100% 收尾 |

**污染红线**：mission 路径不允许「把上游 runOutput 自由文本整个塞进下游 prompt」——只允许 Handoff（summary ≤400 字 + citations）。这是与现有 Loom `runOutput` 注入（1200 字自由文本，`runner.ts:61-70`）的关键差别。

| 驳回类型 | 返工话术（教师批注 → 总指挥转派） | 记忆更新 |
