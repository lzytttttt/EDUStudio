> 一次性收口 P0 / P1 / P2 六项问题，让画布在 API 模式下与 Mock 模式**同一语义、同一边界、同一可见性**。

## 一、背景与目标

评估报告确认了 6 个「真实接入 LLM 后」才暴露的阶段性问题：

| # | 问题（修复前实测） | 影响 |
| --- | --- | --- |
| 1 | 便签节点被当作任务执行（实测 3 次 LLM 调用且产出文档） | 白耗真实 token，语义错误 |
| 2 | 画布文档节点未接线：产出文档后画布不出现节点 | README 承诺的「📄 正在生成」未兑现 |
| 3 | `artifact_*` 事件不写入 `entry.trace` | Trace 空间投影永远无文档项 |
| 4 | 上游只取直接上游：`A → ✋ → B` 时 A 的结果丢失（收到「（暂无文本输出）」） | 人工确认链上下文断档 |
| 5 | 文档生成请求不携带上游上下文 | 下游文档无法承接上游结论 |
| 6 | function-calling 路径无 `plan` 事件；首次失败静默回退 Mock | 轨迹口径割裂 / 降级不可见 |

目标（产品原则）：**便签只是便签、文档节点由产出驱动、依赖既是调度也是信息、降级要让人看见。**

## 二、修复内容与改动文件

### P0-1 · 非执行节点不参与执行（调度语义）

- `src/lib/loomGraph.ts`：新增 `isExecutableNode`（`note` / `artifact` 非执行）；
  `readyNodes` 排除非执行节点，且非执行父节点**不阻塞**下游（便签不挡路）；
- `src/harness/loom/runner.ts`：`planIds` 只取执行型节点 —— 便签不再进入本轮计划、不消耗 LLM 调用；
- `src/apps/loom/LoomPanel.tsx`：「开始处理」可运行数同步口径（按钮禁用态与 runner 判定一致）；
- `src/apps/loom/loomNodeMeta.ts`：移除手动创建「文档」入口（文档节点由产出驱动，不再产生语义死节点）。

### P0-2 · 文档节点接线（产出 → 画布）

- `src/stores/loomStore.ts`：
  - 新增 `ensureArtifactOutputNode`：按 `artifactId` 幂等复用；新节点落在**触发节点右侧**；
    运行态产出**不进 undo 历史**（与 `setNodeRunOutput` 同策略）；
  - 新增 `setArtifactNodeStatus`：`running → done / error` 收口，支持终稿标题刷新；
- `src/stores/chatStore.ts`：
  - `artifact_meta → 建节点（生成中）`、`artifact_done → 置 done + 终稿标题`；
  - `artifact_meta` / `artifact_done` **写入 `entry.trace`**（`artifact_chunk` 不写，避免流式刷屏）；
- `src/harness/loom/runner.ts`：新增 `settleArtifactNodes` —— 节点失败 / 中断时，把本节点产出的
  未完成文档节点置 `error`（不再停留在「正在生成」僵死态）；
- `src/apps/loom/LoomCanvas.tsx`：文档节点「打开」直达右栏（M6 交付补接线）；
- `src/apps/loom/LoomNodeEditor.tsx`：文档节点补充来源说明（Agent 产出自动出现）。

### P1-3 · 上游穿透（信息语义与调度语义分离）

- `src/lib/loomGraph.ts`：新增 `isTextPassthrough`（`note` / `artifact` / `checkpoint` 不产出文本）；
  `collectUpstreamResults` 改为 BFS 收集：
  - 透传节点 → 继续向上穿透；
  - 产出型节点构成**信息边界**（其输出已含更上游成果）→ 收集后停止；
  - 只收录已产出（`done` / `error`）的节点。

> 与 `isExecutableNode` 的区别：`checkpoint` **参与调度**（暂停 / 恢复），但**不构成信息边界**。

### P1-4 · 文档生成注入上游结果

- `src/harness/types.ts`：`ArtifactProvider.generate` 增加可选 `upstream?: LoomUpstreamRef[]`；
- `src/harness/agent/stepRunner.ts`：`StepContext.upstream` 透传（缺省时入参与旧版逐字节一致）；
- `src/harness/artifacts/adapter.ts`：prompt 增加「【上游任务结果】」段（复用 `formatUpstreamResults`）；
- `src/harness/agent/MockOrchestrator.ts`：同契约透传（Mock 模板不消费，仅保持路径一致）。

### P1-5 · function-calling 补 plan + 任务型执行约束

- `src/harness/agent/Orchestrator.ts`：
  - 首轮 `toolCalls` → 补发 `plan` 事件（`planStepsForToolCalls`，业务 label 口径，与对话轨迹 / 画布投影同构）；
  - 任务型目标（`looksLikeTaskGoal`）system 追加 `TASK_EXECUTION_HINT`，降低「只给文字不调工具」白跑一次；
  - `looksLikeTaskGoal` / `taskExecutionHint` / `planStepsForToolCalls` 导出供单测（同一实现）。

### P2-6 · 降级可见

- `src/harness/agent/index.ts`：`FallbackAgent` 回退 Mock 时，若为画布执行上下文（`context.loomNodeId`），
  同步推送画布通知「真实模型调用失败，本节点已回退内置剧本执行」（对话区 reflect 不变）。

## 三、行为变更（对外可观察）

| 变更点 | 变更前 | 变更后 |
| --- | --- | --- |
| 便签节点 | 发起 LLM 调用并被置 `done` | 保持 `idle`，零调用、不阻塞下游 |
| 文档节点 | 不出现 | 生成中（amber 呼吸「正在生成」）→ 完成（mint「已生成」）；双击 / 「打开」直达右栏 |
| Trace 投影 | 无文档项 | 含 artifact 项（标题 + 状态）；`function-calling` 路径含 plan |
| `A → ✋ → B` | B 收到「（暂无文本输出）」 | B 收到 A 的完整输出（穿透注入） |
| 文档生成请求 | 仅目标 + 数据上下文 | 追加「【上游任务结果】」段，承接上游结论 |
| 执行轨迹口径 | function-calling 无 plan、降级路径有 | 两条路径均以 plan 起头 |
| LLM 失败回退 | 仅对话区一条 reflect | 画布 toast 说明降级（不打断对话流） |
| 手动「文档」模块 | 可创建（但不会执行 / 绑定） | 入口移除；历史数据仍可渲染 / 删除 |

## 五、风险与对策

| 风险 | 对策 |
| --- | --- |
| `chatStore → loomStore` 静态依赖推高主 chunk | 实测 +1.0KB（117.9/120 仍守门禁）；loomStore 经 AppShell 本就在主 chunk，未新增模块 |
| 文档节点在画布未打开时创建 | 按角色 `ensureBoard`（与 `ensureTaskNode` 同策略），下次打开即可见，不抢视图 |
| `artifact_*` 入 trace 影响对话区渲染 | `AgentTraceView` 对未处理类型直接忽略；`artifact_chunk` 不写入，避免膨胀 |
| 移除手动「文档」入口的兼容性 | 历史数据中的手动文档节点仍可渲染 / 删除 / 连线（仅不再提供创建入口） |
| Plan-JSON 降级仍可能发生 | system 约束降低概率，三层降级链路（工具 → Plan-JSON → 内置剧本）保持不变 |
| 上游穿透引入过多上下文 | 产出型节点构成边界（不递归收集更早成果）；输出仍按 1200 字 + 6 条工具摘要截断 |
