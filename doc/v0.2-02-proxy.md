# v0.2-02 · 轻后端代理

> 优先级：P0 ｜ 里程碑：M1 ｜ 预估：2~3 人日
> 目标：为 DeepSeek API 提供轻量代理层——统一保管 key、按用户/IP 限额、记录审计日志；前端零业务改动，仅切换 baseUrl。

## 一、背景与目标

浏览器直连 LLM API 必然暴露 key。EDUStudio 面向教育机构（教育局/学校）交付时，key 必须由部署方统一保管。
本专项提供一个**零运维优先**的代理服务，同时保持 v0.1 的轻量定位：不引入数据库、不引入框架重依赖。

**成功判据**：前端设置页填入代理地址（不填 key）→ 全流程可用；超限时返回 429 并在前端友好提示；
代理日志可追溯每次调用的角色与 token 消耗。

## 三、技术方案

### 3.1 接口设计（OpenAI 兼容透传）

```
POST /v1/chat/completions          # 透传 body，代理注入 Authorization
GET  /health                       # 健康检查（含当前限额配置摘要，不含 key）
```

- 代理只允许 `/v1/chat/completions` 单一路径（白名单），其余一律 404 —— 缩小攻击面
- 请求体校验：`model` 白名单（`deepseek-chat` / `deepseek-reasoner`）、`messages` 长度上限（如 100 条）、单条内容长度上限（如 32K 字符）
- 响应：SSE 原样流式转发（见 3.4），非流式 JSON 同样透传

### 3.2 方案 A：Cloudflare Workers（首选，零运维）

```js
// proxy/worker.js 核心逻辑（示意）
export default {
  async fetch(req, env) {
    if (req.method !== 'POST' || new URL(req.url).pathname !== '/v1/chat/completions') {
      return new Response('Not Found', { status: 404 })
    }
    const limited = await rateLimit(env, req)   // KV/DO 计数，见 3.3
    if (limited) return json({ error: 'rate_limited' }, 429)
    const body = await sanitize(req)            // model/messages 白名单校验
    const upstream = await fetch(`${env.UPSTREAM}/chat/completions`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${env.DEEPSEEK_KEY}` },
      body: JSON.stringify(body),
    })
    ctx.waitUntil(audit(env, req, upstream))    // 审计不阻塞响应
    return new Response(upstream.body, {        // body 是流，直接透传 = 天然 SSE
      status: upstream.status,
      headers: { 'Content-Type': upstream.headers.get('Content-Type') ?? 'application/json' },
    })
  },
}
```

- 部署：`wrangler deploy`；key 存 Workers Secrets（`wrangler secret put DEEPSEEK_KEY`）
- 免费额度足够 POC 与小规模试点；无需自己管服务器
- CORS：仅允许部署方的前端域名（env 白名单），拒绝其余来源

### 3.3 方案 B：Node / Express（备选，可自托管）

适用：学校/局内网无法用 Workers、或需完全私有化部署。

- `proxy/server.mjs`：Express + 内置 `express-rate-limit`（内存存储即可，单实例足够）
- SSE 注意点：**关闭 compression**（缓冲会破坏流式）、`res.flushHeaders()` 后 pipe upstream body
- 部署：`node proxy/server.mjs`，env：`DEEPSEEK_KEY / UPSTREAM / RATE_LIMIT_PER_HOUR / ALLOWED_ORIGINS`
- 内网交付场景可加一层最简静态鉴权：请求头 `X-EDU-TOKEN` 与 env 比对（机构内统一分发）

### 3.4 限额与审计

**限额（两级）**：

| 级别 | 维度 | 默认 | 存储 |
| --- | --- | --- | --- |
| 瞬时 | IP / X-EDU-TOKEN | 10 次/分钟 | Workers: KV 计数（TTL 60s）；Express: rate-limit 内存 |
| 日额 | 同上 | 200 次/天（可 env 调） | 同上（TTL 24h） |

- 超限返回 `429 + {error:'rate_limited', retryAfter}`；前端 chatStore 捕获后 toast 提示并保持输入不丢失
- token 级计费限额（按 usage 累计）列为 M2 增强，M1 只做次数限额

**审计（最小可用）**：

- 每次调用记录：时间、IP/token 摘要、角色（前端经 `X-EDU-Client: role:teacher` 传入）、model、状态码、usage tokens（从响应末帧或非流式响应提取）
- Workers 写 KV（按日分 key，保留 30 天）；Express 写本地 JSONL 文件（按日滚动）
- 不记录对话内容明文（合规考虑），仅记录元数据；如需内容审计由部署方在 upstream 侧自行开启

### 3.5 前端接入

- settingsStore 增加 `proxyUrl`；`buildProviders()` 逻辑：`proxyUrl 非空 → adapter 用 proxyUrl 且无需 apiKey`；否则直连（需 key）
- 失败语义与专项 01 一致：429/5xx → 回退 Mock + reflect 条说明

## 五、验收标准

1. **透传**：经代理的流式对话与直连体验一致（逐 token 渲染，无整段延迟）
2. **安全**：前端请求不含 Authorization；错误 key 场景下代理日志无 key 泄露；非白名单路径 404
3. **限额**：连续调用超过 10 次/分钟触发 429，前端 toast 提示且输入保留；次日自动恢复
4. **审计**：KV/JSONL 中可查到每次调用的角色、model、状态码与 token 消耗
5. **部署**：按 proxy/README.md 从零部署 ≤ 15 分钟（Workers）；Express 版 `node server.mjs` 即起
6. **包体**：前端构建产物增量 0KB（代理代码不进包）

## 六、风险与对策

| 风险 | 对策 |
| --- | --- |
| Workers KV 计数有秒级延迟，瞬时限额可能略超 | 限额阈值留 20% 余量；精确计费属 M2（改用 Durable Objects） |
| 内网环境无法访问 Workers | 方案 B 自托管；README 提供内网部署清单（Node 18+、出网白名单 api.deepseek.com） |
| 代理被第三方扫描滥用 | CORS 域名白名单 + 可选 X-EDU-TOKEN；路径白名单；model 白名单 |
| 上游限流传导（DeepSeek 429） | 代理透传 429 与 retryAfter；前端与本地限额共用同一提示通道 |
