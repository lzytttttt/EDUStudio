# v0.8 路线图 · API 模式数据驱动闭环：LLM 全链路真实数据 + 自进化技能提炼落地

> 基于 v0.7 交付现状制定。v0.7 已完成：简报生成增强（Mock 个性化 + API 骨架）/ 卡片内容可交互 /
> 真实落章动效 / 卡片动效优化 / 专注模式。Vitest 125 例全绿。
> v0.8 主线：**补齐 API 模式最后两块骨架——LLM 生成注入真实数据（简报/文档不再编造数字），
> LLM 技能提炼真实落地（API 模式任务完成后自动沉淀/进化技能），让自进化闭环在双模式下都成立**。

## 背景与目标

v0.7 后 API 模式仍有两处「半成品」：

1. **LLM 生成无米之炊**：`ApiBriefingProvider` / `ArtifactApiAdapter` 只拿到角色身份与任务目标，
   拿不到任何真实数据——简报卡片与文档里的数字全靠模型编造，与「数据驱动」定位相悖；
2. **技能提炼 no-op**：`LlmSkillDistiller` 是 v0.6 留下的接口骨架（直接返回 null），
   且 Orchestrator 调用后丢弃返回值——API 模式任务完成后不沉淀技能，
   自进化闭环（发现 → 沉淀 → 复用 → 进化）只在 Mock 模式成立。

v0.8 四项升级：**① 数据上下文层 ② 简报 API 数据驱动 + 重试 ③ 文档生成数据注入
④ LLM 技能提炼落地**。

## 关键设计决策

1. **数据上下文独立成层而非散在调用方**：简报生成、文档生成（及未来 Orchestrator）三处消费同一入口；
   格式化纯函数与异步聚合分离保证可单测；1800 字符截断护栏控制 token 成本。
2. **数据约束写进 prompt 而非后处理**：LLM 拿到真实数据 + 「禁止编造」指令 + 无数据时「定性描述」，
   从生成端消除幻觉数字；来源标注（label · 新鲜度）随数据段进入 prompt，卡片 source 可溯源。
3. **重试一次而非指数退避**：结构化输出失败多为偶发格式问题，两次尝试 + Mock 兜底已覆盖绝大多数场景，
   避免拖长简报首屏等待。
4. **提炼门控（未命中技能且任务型才提炼）**：技能命中说明已有可复用路径（无需重复沉淀），
   寒暄/咨询类无沉淀价值；每次任务省一次 LLM 调用，成本可控。
5. **进化保留原步骤**：LLM 复盘只扩充触发词与元信息，步骤仍以已验证的执行轨迹/原技能为准——
   避免 LLM 幻觉步骤破坏已验证可用的技能（与 v0.6 确定性提炼的合并策略一致）。
