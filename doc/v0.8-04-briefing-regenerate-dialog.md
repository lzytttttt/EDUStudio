# v0.8 增量优化 · 简报自定义重新生成弹窗（交付说明）

> 本专项为 v0.8.3 交付后的小型优化（一项），随 v0.8.4 发布。
> 状态：✅ 已完成 · 单测（157 例，+8）+ tsc 验证通过，零新依赖，Provider 签名为可选参数扩展（既有调用零破坏）；
> 包体按 v0.6 / v0.8 先例重校 260 → 270KB（存量 v0.8.3 follow-up 超限 +2.9KB，本次增量 +3.2KB，实测 266.1KB）。

## 背景与目标

v0.7 起「今日简报」具备完整的滑卡批示体验，v0.8 完成 API 模式数据驱动闭环，但卡组内容始终由
system prompt + 数据上下文一次性决定：用户对「想要什么样的简报」没有表达入口——想多看某学科、
只要某几类卡片、不要图表卡、生成慢一点也要更稳，都只能被动接受。

本次在简报页顶栏新增「重新生成」入口：悬浮弹窗让用户表达偏好（提示词 / 简报种类 / 参考资料 /
高级自定义），确认后按当前模式重载卡组：

1. **API 模式**：选项注入生成 prompt（自定义要求、种类约束、数量、风格、payload 要求、参考资料段落开关），
   超时与重试次数可调（有 clamp 边界）；
2. **Mock 模式**：按所选种类过滤静态剧本（提示词与高级选项不生效，界面注明）；
3. **偏好记忆**：选项随 LocalStorage 持久化，下次打开弹窗回填，刷新 / 重播同样生效。

## 实现

### 改动一：选项契约与生成链路（`harness/types.ts` + `harness/briefing/ApiBriefingProvider.ts` + `MockBriefingProvider.ts`）

| 项 | 说明 |
| --- | --- |
| 契约扩展 | `BriefingGenOptions`：`prompt`（≤200 字）/ `types`（六类卡片，空/全选 = 不限）/ `references`（dataContext / decisions / favorites 三开关，默认全开）/ `count`（3-10，缺省 = 默认 5-7）/ `style`（concise / detailed / data，缺省跟随角色 system prompt）/ `payloads`（chart / options / todos，默认全开）/ `timeoutMs`（6000-30000，默认 12000）/ `maxAttempts`（1-3，默认 2）；`BriefingProvider.getDeck/getDeckAsync` 增加可选第三参 `options?` |
| 约束注入 | 原 `CARD_SCHEMA_PROMPT` 写死的「5-7 张 / 类型多样 / 至少 2 张带 payload」拆为 `composeGenConstraints(options?)` 动态拼装：数量段、种类白名单段（`卡片类型仅限：insight|data`）、风格段、payload 段（全关 = 纯文本卡）；非法种类值被过滤 |
| 提示词注入 | `composeBriefingUser` 追加【自定义要求】段（trim + 200 字 clamp），置于数据上下文之后、输出格式之前 |
| 参考资料开关 | `references` 三开关分别控制「真实数据上下文 / 历史决策 / 收藏卡片」三段是否注入 prompt（`dataText` 为空串时本就跳过数据段，沿用既有容错） |
| 参数化生成 | `attempt(...)` 的超时与重试上限由常量改为按 options clamp（`clampGenTimeout` 6-30s / `clampGenAttempts` 1-3 次，默认值不变）；`getDeckAsync(role, ctx, options?)` 全程透传，失败仍走既有「重试 + Mock 兜底」链路 |
| Mock 过滤 | `MockBriefingProvider.getDeck(role, ctx, options?)` 按 `options.types` 过滤 `BRIEFING_DECKS`（空选 / 全选 = 不过滤），个性化排序逻辑保持不变 |

### 改动二：选项记忆（`stores/briefingStore.ts`）

| 项 | 说明 |
| --- | --- |
| 状态与持久化 | 新增 `genOptions` 状态 + `setGenOptions`，随既有 `'briefing'` key 一并持久化（读回合并默认 `{}`） |
| 透传策略 | `loadDeck(role, options?)` 显式传入优先，否则沿用已存 `genOptions`——刷新页面、CSV 导入后刷新、「重新过一遍」同样带着偏好生效 |

### 改动三：重新生成弹窗（新建 `apps/briefing/RegenerateDialog.tsx`）

| 分区 | 说明 |
| --- | --- |
| 头部 | Wand2 图标（primary 圆角方块）+「重新生成简报」标题 + 副标题「按你的偏好重新生成今日简报」+ 关闭按钮 |
| 提示词 | 多行 textarea（示例 placeholder），右下角字数计数（≤200，`GEN_PROMPT_MAX_LEN`），聚焦 primary 描边；标注「仅 API 模式生效」 |
| 简报种类 | 六类卡片多选 chip（洞察 / 决策 / 创作 / 待办 / 数据 / 提问），选中态 `bg-primary-soft text-primary`，附「全选 / 清空」快捷切换；不勾选 = 不限 |
| 参考资料 | 三个 checkbox 行：真实数据上下文（按角色动态命名：班级学情数据 / 校情数据与预警 / 区域指标数据）、历史决策、收藏卡片，各带一行说明 |
| 高级自定义 | 折叠面板（默认收起）：卡片数量（「默认 5-7 张」+ 3-10 步进器，可重置）、内容风格（默认 / 简洁扼要 / 详细展开 / 数据导向 单选胶囊）、交互卡片（图表 / 选项 / 待办 checkbox）、生成参数（单次超时 6-30s 步进 + 失败重试 1-3 次，标注仅 API 生效） |
| Mock 提示条 | `mode === 'mock'` 时显示琥珀色提示条：「当前为演示模式：仅简报种类过滤生效；提示词与高级选项在 API 模式下生效」 |
| 交互 | 打开时从 store `genOptions` 回填；确认回调携带整理后的选项（空值归一为 undefined = 既有默认）；遮罩点击 / ESC 关闭；弹窗内滚动（`max-h` + `overflow-y-auto`）；浮层范式对齐 `FocusTaskSheet`（`bg-ink/30` 遮罩 + `backdrop-blur-sm` + `animate-fade-up` + `rounded-3xl` surface 卡） |

### 改动四：顶栏接线（`apps/briefing/BriefingPage.tsx`）

| 项 | 说明 |
| --- | --- |
| 入口按钮 | 顶栏「重新生成」按钮（Wand2 图标），与「刷新数据」「导入成绩」并列同款式，移动端只显图标；随时可点（不与批示互斥） |
| 确认流程 | `handleRegenerate`：保存选项（`setGenOptions`）→ 清保留层 → `resetDeck()`（清决策 / 覆盖层，收藏保留）→ 重播卡牌切入动画（`INTRO_ELIGIBLE` 门控，对齐「重新过一遍」）→ `loadDeck(role, options)`；生成期间走既有骨架屏 / 切入动画等待路径 |

### 兼容性

- **Provider 签名零破坏**：`options` 为可选第三参，既有调用点（刷新 / 导入后刷新 / 重播）不传即沿用已存偏好或默认行为；
- **E2E / 视觉回归零影响**：弹窗仅点击时挂载，不触碰引导门控与卡组初始路径；
- **失败兜底不变**：API 生成失败仍走「clamp 内重试 + Mock 兜底」，参数可调但不会拖垮首屏；
- **Mock 模式边界清晰**：仅种类过滤生效，提示词与高级选项不生效且界面注明，不产生「改了没反应」的误解。

### 包体预算重校（v0.6 / v0.8 先例）

实测发现 v0.8.3 基线已超限：v0.8.3 follow-up 打磨（login / shell / share / guide / i18n / exporters）
引入约 +2.9KB 但未随重校，基线实测 262.9KB > 260KB（存量潜伏超限）。本次弹窗增量 +3.2KB（主 chunk
96.6 → 99.7KB，仍在 110KB 预算内），实测 266.1KB。按 `scripts/budget.mjs` 既有校准先例
（基线 + 增量 + 余量）重校为 **270KB**，并在注释中留痕。
